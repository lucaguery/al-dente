    ### B. Replace the existing `onSubmit` function (lines 117-149)

    The current `onSubmit` uses `api<JoinResponse>(...)` which throws away the response body. We swap to a raw `fetch()` so we can read `body.detail.code` on 422. The rest of the error-handling shape is preserved.

    ```ts
    async function onSubmit() {
      if (!canSubmit || !color) return;
      setSubmitting(true);
      setColorError(null);
      try {
        const API_BASE = process.env.NEXT_PUBLIC_API_BASE ?? "";
        const res = await fetch(`${API_BASE}/api/households/join`, {
          method: "POST",
          credentials: "include",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({
            invite_code: code,
            member_name: memberName.trim(),
            color_hex: color,
          }),
        });
        if (res.ok) {
          await refresh();
          router.replace("/");
          return;
        }
        // Parse body to discriminate 422 HOUSEHOLD_FULL vs plain 422 vs 409 vs 404.
        let parsed: { detail?: unknown } = {};
        try {
          parsed = await res.json();
        } catch {
          // Body wasn't JSON — fall through to network toast below.
        }
        if (res.status === 404) {
          setCodeError(tErrors("code_not_found"));
        } else if (
          res.status === 422 &&
          parsed.detail &&
          typeof parsed.detail === "object" &&
          (parsed.detail as { code?: unknown }).code === "HOUSEHOLD_FULL"
        ) {
          // IDM-04 / D-18-12: structured capacity error → terminal Card.
          setHouseholdFull(true);
        } else if (res.status === 409 || res.status === 422) {
          // Color taken (409) OR Pydantic palette validation (legacy 422).
          // Refresh preview so the now-taken color shows as disabled.
          setColorError(tErrors("color_taken"));
          setColor(null);
          await fetchPreview(code);
        } else {
          toast.error(tErrors("network"));
        }
      } catch {
        // Network error (offline, DNS, etc.).
        toast.error(tErrors("network"));
      } finally {
        setSubmitting(false);
      }
    }
    ```

    The existing `statusOf()` helper (lines 43-49) can stay (unused by the new fetch path but used elsewhere indirectly via `fetchPreview`'s catch — preserve it).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| onboarding/join → POST /households/join | Untrusted invite_code + member_name + color_hex crosses to the backend. No auth required (this IS the auth-establishment surface). |
| backend 422 body → frontend discriminator | Parsed JSON detail.code drives a state branch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-03-01 | Tampering | Forged 422 body with code:"HOUSEHOLD_FULL" | accept | The 422 only renders a terminal Card with a back CTA — there's no privilege or data exposure on the rendered Card. A MITM attacker who can rewrite responses can already redirect onboarding entirely; the worst-case from this branch is a denial-of-onboarding for a single user, not a privilege escalation. |
| T-18-03-02 | XSS | Card renders translation strings | accept | `t("capacity.*")` returns the next-intl-bundled French strings as plain text into JSX — auto-escaped by React. No interpolation of user input into the Card body. |
| T-18-03-03 | Information Disclosure | Capacity body reveals 5-member cap | accept | The cap IS public knowledge — every onboarding screen via `HouseholdPreview` already reveals the 5-color palette by graying out taken swatches. No new information disclosed. |
| T-18-03-04 | Denial of Service | Rapid retries against 422 path | accept | Couple-scale, no rate limit. The terminal Card hides the form so the user cannot retry on this surface — they have to navigate back, by design. |
</threat_model>
