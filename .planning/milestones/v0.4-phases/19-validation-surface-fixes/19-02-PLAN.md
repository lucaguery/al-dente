<objective>
Close FIX-02 / SEED-01: make `uv run seed` cross-day idempotent.

Today the `run_test_seed` function generates UUIDs for the 3 seeded `CookingLog` rows and the 1 seeded `DailyShortlist` row using `_id("cooking_log", slug, str(cooked_at.date()))` and `_id("shortlist", today.isoformat())`. When the calendar day advances, those date strings change → uuid5 derives different UUIDs → `db.merge()` inserts new rows instead of updating in place. After N days, the test DB accumulates `3 * N` cooking_log rows and `N` shortlist rows. Operators hit `docker compose down -v` as a workaround.

The prod-synthetic path (`run_prod_synthetic_seed`, lines 770-820) already does the right thing — it uses `_id_synth("cooking_log", slug)` and `_id_synth("shortlist", "today")` with the comment `# NO DATE in key — D-10/D-11`. Test-seed needs the same surgery.

Add a new pytest (`backend/tests/test_seed_idempotency.py::test_seed_cross_day_no_duplicates`) that calls `run_test_seed()` twice and asserts CookingLog + DailyShortlist row counts stay flat. The test monkeypatches `datetime.now` so the second call simulates "day D+1" without waiting 24h.

Purpose: SEED-01 was the last v0.2.2 backlog item gated on a workflow workaround. Closing it removes the `docker compose down -v` step from the daily dev loop.

    Create `backend/tests/test_seed_idempotency.py`. The test uses raw SQLAlchemy `select(func.count(...))` against the test DB (the conftest `db_session` fixture is connection-scoped + rolled back, but the seed commits via its OWN `SessionLocal()` — so the rolled-back fixture won't see the seed's data and won't roll it back. The test must do its own cleanup.):

    ```python
    """FIX-02 / SEED-01 — cross-day idempotency for `uv run seed`.

    The seed CLI uses its own SessionLocal() and commits its own transactions,
    so the conftest db_session rollback fixture does NOT clean up after it.
    This test does its own DELETE pass at the end, scoped to the test household
    id (_id("household", "luca")).
    """
    from __future__ import annotations

    from datetime import datetime, timedelta, timezone
    from uuid import UUID

    import pytest
    from sqlalchemy import func, select, text

    from app.cli import seed as seed_mod
    from app.cli.seed import _id, run_test_seed
    from app.db import SessionLocal
    from app.models.cooking_log import CookingLog
    from app.models.daily_shortlist import DailyShortlist
    from app.models.household import Household
    from app.models.member import Member
    from app.models.recipe import Recipe
    from app.models.vote import Vote


    TEST_HOUSEHOLD_ID: UUID = _id("household", "luca")


    def _snapshot_counts(db) -> dict[str, int]:
        recipes = db.scalar(
            select(func.count(Recipe.id)).where(Recipe.household_id == TEST_HOUSEHOLD_ID)
        ) or 0
        cooking_logs = db.scalar(
            select(func.count(CookingLog.id)).where(CookingLog.household_id == TEST_HOUSEHOLD_ID)
        ) or 0
        shortlists = db.scalar(
            select(func.count(DailyShortlist.id)).where(DailyShortlist.household_id == TEST_HOUSEHOLD_ID)
        ) or 0
        votes = db.scalar(
            select(func.count(Vote.id))
            .join(DailyShortlist, Vote.shortlist_id == DailyShortlist.id)
            .where(DailyShortlist.household_id == TEST_HOUSEHOLD_ID)
        ) or 0
        return {
            "recipes": int(recipes),
            "cooking_logs": int(cooking_logs),
            "shortlists": int(shortlists),
            "votes": int(votes),
        }


    def _cleanup() -> None:
        """Hard-DELETE everything the seed produced for the test household."""
        with SessionLocal() as db:
            db.execute(
                text("DELETE FROM votes WHERE shortlist_id IN ("
                     "SELECT id FROM daily_shortlists WHERE household_id = :h)"),
                {"h": TEST_HOUSEHOLD_ID},
            )
            db.execute(text("DELETE FROM cooking_logs WHERE household_id = :h"), {"h": TEST_HOUSEHOLD_ID})
            db.execute(text("DELETE FROM daily_shortlists WHERE household_id = :h"), {"h": TEST_HOUSEHOLD_ID})
            db.execute(text("DELETE FROM recipes WHERE household_id = :h"), {"h": TEST_HOUSEHOLD_ID})
            db.execute(text("DELETE FROM members WHERE household_id = :h"), {"h": TEST_HOUSEHOLD_ID})
            db.execute(text("DELETE FROM households WHERE id = :h"), {"h": TEST_HOUSEHOLD_ID})
            db.commit()


    @pytest.fixture(autouse=True)
    def _cleanup_around_test():
        """Ensure a clean slate before and after — the seed merges on stable UUIDs
        but other tests may have inserted unrelated rows under the same household_id."""
        _cleanup()
        yield
        _cleanup()


    def test_seed_cross_day_no_duplicates(monkeypatch: pytest.MonkeyPatch) -> None:
        """FIX-02 — seed re-run on a later calendar day must not insert new rows.

        Monkeypatches datetime.now (used at seed.py:380) so the second call
        simulates day D+1 without waiting 24h.
        """
        # ---- 1st run: day D ----
        day_d = datetime(2026, 6, 1, 12, 0, 0, tzinfo=timezone.utc)

        class _FrozenDateTime(datetime):
            @classmethod
            def now(cls, tz=None):  # type: ignore[override]
                return day_d if tz is None else day_d.astimezone(tz)

        monkeypatch.setattr(seed_mod, "datetime", _FrozenDateTime)
        # date.today() reads its own clock; the seed pulls today via date.today() too.
        # For test-seed the `date` column on DailyShortlist tracks today, but the
        # UUID no longer depends on it, so monkeypatching just datetime is enough
        # to assert the UUID-stability property.
        run_test_seed()

        with SessionLocal() as db:
            first = _snapshot_counts(db)

        # Sanity — first run produced the canonical shape.
        assert first["recipes"] == 21, first
        assert first["cooking_logs"] == 3, first
        assert first["shortlists"] == 1, first
        assert first["votes"] == 7, first  # 2+1+2+2+0 per vote_specs at seed.py:506-513

        # ---- 2nd run: day D+1 ----
        day_d_plus_1 = day_d + timedelta(days=1)

        class _FrozenDateTimePlus1(datetime):
            @classmethod
            def now(cls, tz=None):  # type: ignore[override]
                return day_d_plus_1 if tz is None else day_d_plus_1.astimezone(tz)

        monkeypatch.setattr(seed_mod, "datetime", _FrozenDateTimePlus1)
        run_test_seed()

        with SessionLocal() as db:
            second = _snapshot_counts(db)

        # The whole point: counts must be FLAT across the day boundary.
        assert second == first, (
            f"FIX-02 regression: seed re-run on day D+1 produced different "
            f"row counts. first={first} second={second}"
        )
    ```

    A few sharp edges to honor:
    - `monkeypatch.setattr(seed_mod, "datetime", _FrozenDateTime)` substitutes the SYMBOL the seed imported at module top (`from datetime import ... datetime ...`). The test wraps `datetime.now()` calls inside `run_test_seed`. `date.today()` is NOT monkeypatched — the DailyShortlist.date column will hold the real `today` for both runs, which is fine: the UUID is stable, so merge UPDATEs the same row regardless.
    - The seed's `_guard_environment` enforces `settings.environment == "test"` and `"aldente_test" in settings.database_url`. The pytest CI config in `conftest.py` already targets `aldente_test` on port 5433. If the local env hasn't set `ENVIRONMENT=test`, the test will sys.exit — that's the seed's own safety guard, NOT a test bug. Document this dependency in a top-of-file docstring.
    - The autouse `_cleanup_around_test` fixture is intentional — without it, a previous failed test run would have stale rows lying around that the assertion `first["recipes"] == 21` would miscount.
