## Decisions Made

- **Renamed `middleware.ts` → `proxy.ts`** — Next.js 16 deprecates `middleware.ts` in favor of `proxy.ts` (matcher behavior unchanged). Caught at `npm run build` by a deprecation warning. Auto-fixed during Task 1; the rename is a Rule-3 deviation noted below.
- **Vercel deployed via CLI, not push-to-main yet** — first prod URL (`al-dente-pink.vercel.app`) was shipped via `vercel --prod` from a manually-authenticated CLI session. The GitHub→Vercel webhook can be wired through the Vercel dashboard later (Project Settings → Git). The W1 install gate only requires a working installable URL, not push-to-deploy.
- **Placeholder app icons (black AD on dark background)** — the `frontend/public/icons/{192,512}.png` are programmatically generated placeholders, not the final branded artwork. Acceptable for v0.1 dogfood; productize-later TODO is to replace before any wider distribution.
- **shadcn primitives over a managed library (e.g., MUI, Mantine)** — primitives copied in let us edit JSX/CSS directly without fighting library theming. Keeps `package.json` lean (only Radix sub-primitives the components actually need).
- **`api.ts` base URL is read at request time, not at build time** — `NEXT_PUBLIC_*` env vars are inlined into the client bundle by Next, but reading via a helper centralizes the lookup so a future swap to runtime config (e.g., for multi-tenant) is one-file.
