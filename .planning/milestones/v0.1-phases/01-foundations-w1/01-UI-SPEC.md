## Spacing Scale

Tailwind v4 default spacing unit is `0.25rem` (4px). UI-SPEC commits to a strict 4-multiple subset. The planner and executor MUST use these tokens (e.g. `p-4` = 16px, `gap-3` = 12px) and avoid arbitrary `[17px]`-style values.

| Token | Value | Tailwind utility | Usage |
|-------|-------|------------------|-------|
| `space-0` | 0 | `p-0`, `gap-0` | Reset |
| `space-1` | 4px | `p-1`, `gap-1` | Inline icon gaps inside chips/badges |
| `space-2` | 8px | `p-2`, `gap-2` | Compact element spacing (chip padding x, label-to-input gap) |
| `space-3` | 12px | `p-3`, `gap-3` | Tight stack spacing (form field internals) |
| `space-4` | 16px | `p-4`, `gap-4` | **Default container padding**, default vertical rhythm between form fields |
| `space-5` | 20px | `p-5`, `gap-5` | Card body padding |
| `space-6` | 24px | `p-6`, `gap-6` | **Page horizontal padding**, section breaks within a screen |
| `space-8` | 32px | `p-8`, `gap-8` | Large section gaps, modal body padding |
| `space-12` | 48px | `pt-12`, `gap-12` | Major hero/empty-state vertical breathing room |
| `space-16` | 64px | `pt-16` | Onboarding-screen top padding (welcome screen) |

### Mobile baseline

- **Page horizontal padding:** `px-6` (24px) on every screen — feels generous on iPhone 14 (390pt) without being wasteful. Bottom-nav screens add `pb-24` to clear the 64px nav + 16px safe-area-aware breathing room.
- **Form field vertical gap:** `gap-4` (16px) between fields inside a form.
- **Section break (within a screen):** `gap-6` (24px) between visually distinct groups.

### Exceptions

| Exception | Value | Rationale |
|-----------|-------|-----------|
| Tap target minimum | 44px (iOS HIG) | shadcn Button `size="default"` is `h-10` (40px) — Phase 1 overrides to `h-11` (44px) for primary CTAs and bottom-nav items. Icon-only buttons use `h-11 w-11`. |
| Bottom-nav height | 64px (`h-16`) | Comfortable thumb reach on iPhone with `pb-[env(safe-area-inset-bottom)]` honoring iOS home-indicator. |
| Safe-area insets | `env(safe-area-inset-top)` / `bottom` | Used on layout root + bottom-nav. **Required** for iOS PWA install (otherwise content goes under the notch / home-indicator). |

## Typography

Tailwind v4 default font sizes carried forward; UI-SPEC pins exactly **4 sizes** + **2 weights** for the entire Phase 1 surface area. Geist Sans for all UI; Geist Mono reserved for the invite code only.

| Role | Size | Weight | Line Height | Tailwind utility | Usage |
|------|------|--------|-------------|------------------|-------|
| **Body** | 16px (`1rem`) | 400 (regular) | 1.5 (24px) | `text-base font-normal leading-6` | Default for paragraphs, recipe ingredients/steps, form input value |
| **Label / Meta** | 14px (`0.875rem`) | 500 (medium) | 1.43 (20px) | `text-sm font-medium leading-5` | Form labels, chip labels, tab labels, "il y a 3 jours" meta, badge counts |
| **Heading (section)** | 20px (`1.25rem`) | 600 (semibold) | 1.4 (28px) | `text-xl font-semibold leading-7` | Recipe detail title, section titles within a page, modal titles |
| **Display (screen title)** | 28px (`1.75rem`) | 600 (semibold) | 1.21 (34px) | `text-[28px] font-semibold leading-[34px] tracking-tight` | Onboarding "Al Dente" wordmark, primary screen H1 (e.g., "Recettes") |

### Weight rule

**Only 400 (regular) and 600 (semibold)** — no italic, no 500/700 mixed in. Label uses 500 (medium) as the single exception because Geist 500 is visually distinct from 400 at 14px and 600 looks too heavy at small sizes. Total weight count: 3 — but `font-medium` is reserved exclusively to the Label role; everywhere else is 400 or 600.

### Invite-code display

```
text-[28px] font-mono font-semibold tracking-[0.3em]
```

Invite code (e.g., `ABC123`) is the only Mono-font usage in Phase 1. Wide letter-spacing (`tracking-[0.3em]`) makes the 6 characters readable when the partner reads them off-phone.

### French copy guidance

- **Decimal separator:** comma (`12,5 cl`), not period.
- **Quotation marks:** « guillemets français » with non-breaking spaces (` `) inside, OR straight `"…"` if the i18n catalog can't reliably escape NBSPs. Pick one in `fr.json` and stay consistent.
- **Apostrophes:** prefer typographic `'` (U+2019) in static copy; straight `'` is acceptable in input placeholders to keep the TS file readable.
- **Capitalization:** sentence-case for everything except the wordmark "Al Dente" — French does not title-case headings.
- **Numerals:** `Intl.NumberFormat('fr-FR')` for any number > 999 (`1 234`).

### Relative dates

`last_cooked_at` and `created_at` render as French relative time:

```ts
new Intl.RelativeTimeFormat('fr', { numeric: 'auto' }).format(-3, 'day')
// → "il y a 3 jours"
```

Helper `formatRelativeFr(date: Date | null): string` lives in `frontend/lib/datetime.ts`. Returns `"jamais cuisiné"` when `null`.

### Pluralization

`next-intl` ICU MessageFormat plural rules:

```
{count, plural, =0 {Aucune recette} one {1 recette} other {# recettes}}
```

Use this pattern for: drafts count badge (`À compléter (N)`), recipe count headers, photo count ("3 photos").

## Color

### Surface palette (60/30/10)

Built on Tailwind v4 default neutrals. CSS variables live in `app/globals.css` (extends the existing `@theme inline` block). Light mode is the baseline; dark mode is auto-applied when iOS `prefers-color-scheme: dark` (the existing `globals.css` already wires this — Phase 1 keeps it).

| Role (60/30/10) | Light value | Dark value | Tailwind v4 ref | Usage |
|-----------------|-------------|------------|-----------------|-------|
| **Dominant (60%) — surface** | `#FFFFFF` | `#0A0A0A` | `--color-background` (existing) | Page background, sheet/modal background |
| **Secondary (30%) — surface-muted** | `#F4F4F5` (zinc-100) | `#18181B` (zinc-900) | `--color-surface-muted` (NEW) | Cards, list-row hover, bottom-nav background, drafts inbox empty card |
| **Border** | `#E4E4E7` (zinc-200) | `#27272A` (zinc-800) | `--color-border` (NEW) | Card borders, divider lines, input borders |
| **Foreground** | `#171717` (existing) | `#EDEDED` (existing) | `--color-foreground` (existing) | Primary text |
| **Foreground-muted** | `#52525B` (zinc-600) | `#A1A1AA` (zinc-400) | `--color-foreground-muted` (NEW) | Meta text ("il y a 3 jours"), helper labels, placeholder text |
| **Accent (10%) — primary action** | `#0A0A0A` (existing `--color-foreground`) | `#FAFAFA` | `--color-primary` (NEW; aliases foreground in light, near-white in dark) | Primary CTA buttons, active tab indicator, tab badge |
| **Destructive** | `#DC2626` (red-600) | `#EF4444` (red-500) | `--color-destructive` (NEW) | Delete-recipe confirmations, error toasts (background tint), 401-blocked banner |

### Accent reserved for (explicit list — never "all interactive elements")

The 10% accent is `--color-primary` (high-contrast neutral, not a hue) and is reserved for:

1. **Primary CTA buttons** — "Créer un foyer", "Rejoindre", "Enregistrer la recette", "Ajouter une photo".
2. **Active tab indicator** in the bottom nav (a 2px top-bar on the active tab).
3. **The drafts-tab count badge background** (`À compléter (3)` — the `(3)` chip).
4. **Form submit-button at idle** (becomes destructive only on validation error in destructive flows).

It is **not** used for: links inside body text (those are `font-medium` + underline-on-tap, no color change), chip backgrounds (those use `surface-muted`), nav-tab labels (foreground-muted when inactive, foreground when active).

**Rationale:** at couple-scale we want the app to feel like a notebook, not a SaaS dashboard. A high-contrast neutral primary preserves the "just us / domestic" register. The 5 member colors carry all the personality.

## Copywriting Contract

All strings live in `frontend/lib/i18n/fr.json` keyed by surface (e.g. `onboarding.welcome.title`). NO hardcoded JSX strings. Voice register is **informal `tu`** (Luca speaks French at home with his partner). Tone: warm, domestic, no corporate phrasing, no exclamation points unless celebratory, no "Oups !" or "Désolé !" infantilization.

| Surface | Heading | Body | CTA |

### Error states

Errors are **inline** (under the offending field) for form validation and **toast** (top, `Sonner` from shadcn) for network/API errors. Toasts auto-dismiss after 5s except `destructive` variant which persists until dismissed.

| Surface | Copy | Placement |
|---------|------|-----------|
| Required field empty (form) | `Champ requis` | Inline, under field, `text-sm text-destructive` |
| Invite code wrong format | `Le code doit faire 6 caractères` | Inline |
| Invite code not found (server 404) | `Ce code n'existe pas. Vérifie auprès de ta partenaire.` | Inline, under input |
| Color already taken (join flow) | (no error — disabled swatch carries the message visually) | (visual) |
| Network error generic | `Connexion impossible. Réessaie dans un instant.` | Toast, `variant="destructive"` |
| 401 (token invalidated) | `Session expirée. Reconnecte-toi.` | Full-page redirect to onboarding (auth wipe) |
| 500 server error | `Quelque chose a planté côté serveur. Réessaie ou note ce qui s'est passé.` | Toast, `variant="destructive"` |

### Destructive confirmations

Destructive actions in Phase 1 are limited (the data model is mostly additive in W1). When a destructive action is added, use the shadcn `AlertDialog` pattern:

| Action | Trigger | Confirmation copy | Confirm button |
|--------|---------|-------------------|----------------|

## Interaction Patterns

### Forms

- **Validation:** server-validated on submit (HTTP 422 → inline error). **No live JS validation in W1** for required fields except: invite-code length check (6 chars) on the join screen, and field-level `required` HTML attribute for screen reader hints.
- **Submit:** `<form action={serverAction}>` style (Next.js 16 App Router) where possible; otherwise `<Button onClick={handleSubmit}>`. Submit button disables + spinner while in-flight.
- **Error placement:** under the offending field, `text-sm text-destructive`, `aria-describedby` wired to the input.
- **Focus management:** on form open, focus the first text input (autofocus on the first `Input`). On error, focus the first invalid field.

### Optimistic UI for realtime path

REALTIME-02 broadcasts `recipe.created` to both phones. UI rule:

- The **creator's** phone updates the list optimistically (the recipe row is added to the top of the list immediately on submit-success — before the WS event echoes back).
- The **partner's** phone updates from the WS event silently — the new row slides into the list with a 200ms `motion-safe:animate-in` (use Tailwind v4 keyframe utility or framer-motion `<AnimatePresence>` if simpler). **No toast.** The list-update IS the notification.
- If the WS event arrives before the creator's HTTP response, dedupe by `recipe.id` (don't double-render).

### Toast vs inline rules

| Situation | Pattern |
|-----------|---------|
| Field validation error | Inline |
| Network error / API 5xx | Toast |
| API 401 | Full-page redirect (no toast) |
| API 404 (e.g. invite code) | Inline |
| Success (recipe saved, recipe edited) | Toast (5s, default variant) |
| Partner action visible (recipe.created from partner) | List update only, no toast |

### Confirmation patterns

- **Destructive actions:** `AlertDialog` with explicit destructive button (`variant="destructive"`).
- **Soft-destructive (remove a photo):** instant action + 5s undo toast. No modal.
- **Non-destructive form abandonment** (e.g. tapping back on `/recipes/new` with unsaved changes): **no warning in W1** — productize-later. Couple-scale audience accepts the cost.

### Tap targets

All interactive elements ≥44×44px. shadcn `Button size="default"` is `h-10` (40px) by default — Phase 1 overrides primary CTAs to `h-11` (44px). Icon-only buttons are `h-11 w-11`. Bottom-nav tab cells are ≥44×80.

### Search behavior (RECIPE-03)

- **Debounce:** 300ms after last keystroke before firing `GET /recipes?q=...`.
- **Min query length:** 1 (single character is fine, ILIKE handles it).
- **Empty query:** show full paginated list.
- **Loading state:** `Loader2` icon adornment in the input.
- **No-results:** swap list for `EmptyState` with `Aucun résultat pour « {query} »`.

## Motion

Phase 1 motion is minimal — `framer-motion` enters in Phase 3 for the swipe deck. Phase 1 uses Tailwind v4 utility transitions only.

| Token | Duration | Easing | Usage |
|-------|----------|--------|-------|
| `motion-fast` | 150ms | `ease-out` | Hover/active state changes, button color shifts |

### `prefers-reduced-motion`

Honor `@media (prefers-reduced-motion: reduce)`:
- All entrance animations replaced with instant render.
- Tailwind `motion-safe:` and `motion-reduce:` prefixes used for any custom animation.

This is non-negotiable for accessibility and is checked into `app/globals.css` as a global rule.

## Accessibility

### Focus rings

shadcn primitives ship with `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2` by default — keep this. Even though most usage is touch, focus rings matter for screen-reader users with switch control on iOS.

### Screen-reader labels

All `Button size="icon"` MUST have `aria-label` (in French): e.g. `<Button size="icon" aria-label="Modifier la recette">`. Linter-level enforcement: `eslint-plugin-jsx-a11y` is part of `eslint-config-next`; trust the default rules.

### Color contrast

D-04 already validates the 5 member colors against WCAG-AA on white and dark surfaces. Other contracts:
- Body text (`#171717` on `#FFFFFF`): ratio 17.4 — AAA ✓
- Foreground-muted (`#52525B` on `#FFFFFF`): ratio 7.2 — AAA ✓
- Destructive (`#DC2626` on `#FFFFFF`): ratio 4.83 — AA ✓ (AAA needed for body text but destructive is for emphasis at ≥14px which only needs AA)

Dark-mode contrast values verified during the same pass.

### Tap targets

All ≥44×44 (iOS HIG). Reiterated: Button `default` size is bumped to `h-11` for Phase 1.
