## Key Decisions

### Task 2: Route Handler Not Created — beforeFiles Rewrites Win

The plan's Task 2 posed the question: does Next.js 16 resolve rewrites before app/api Route Handlers?

**Answer confirmed from `frontend/node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/rewrites.md`:**

App Router request order:
1. headers
2. redirects
3. proxy
4. **beforeFiles rewrites** ← our rewrites land here
5. static files + pages (including Route Handlers) ← filesystem check
6. afterFiles rewrites
7. fallback rewrites

A simple `return [...]` from `rewrites()` is treated as `afterFiles` (step 6), which comes AFTER the filesystem (step 5). That would mean a Route Handler at `app/api/auth/session/route.ts` would be served before the rewrite — breaking the proxy.

**Fix applied (deviation from plan template):** Used `return { beforeFiles: [...] }` instead of `return [...]`. This places rewrites at step 4, before the filesystem, guaranteeing the proxy intercepts `/api/*` even if Route Handlers exist.

Result: `frontend/app/api/auth/session/route.ts` is NOT created. The `beforeFiles` rewrite `source: "/api/:path*"` → `${RAILWAY_BASE}/:path*` intercepts `DELETE /api/auth/session` before Next.js checks for a handler. Cookie clear on logout/1008 is handled transparently.

### RAILWAY_URL is server-only

`RAILWAY_URL` has no `NEXT_PUBLIC_` prefix. Next.js only inlines `NEXT_PUBLIC_` vars into the browser bundle. `RAILWAY_URL` is consumed only in `next.config.ts` at build/request time on the server — never shipped to the browser. Threat T-01.1-03-01 mitigated by naming convention.

### Build-time fail-fast guard

```typescript
if (!RAILWAY_URL) {
  throw new Error(
    "RAILWAY_URL env var is required. Set it in Vercel Project Settings " +
      "(production) and frontend/.env.local (dev, e.g. http://localhost:8000).",
  );
}
```

Confirmed working: `unset RAILWAY_URL && node next.config.ts` throws immediately with the message above. Threat T-01.1-03-03 mitigated.

**Found during:** Task 2 analysis

**Issue:** Plan template showed `return [...]` (simple array) which maps to `afterFiles`. Per the rewrites docs, afterFiles are checked AFTER the filesystem — meaning Route Handlers would win over the rewrite. Any future Route Handler at `app/api/*` would shadow the Railway proxy.
