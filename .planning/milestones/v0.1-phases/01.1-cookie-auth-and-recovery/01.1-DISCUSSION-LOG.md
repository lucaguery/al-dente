## Cookie plumbing

| Option | Description | Selected |
|--------|-------------|----------|
| Next.js rewrites | `/api/*` → Railway proxy; Set-Cookie passes through; api.ts drops Bearer header | ✓ |
| Next.js API route proxy | Dedicated `app/api/auth/route.ts` explicitly sets cookie; only auth endpoints proxied | |

**User's choice:** Next.js rewrites (all `/api/*` proxied)

---

### Bearer fallback

| Option | Description | Selected |
|--------|-------------|----------|
| Dual-mode (cookie + Bearer) | Backend accepts cookie first, falls back to Bearer header | ✓ |
| Cookie only | Clean break; Bearer header rejected after migration | |

**User's choice:** Dual-mode — Bearer fallback preserved for local dev and existing sessions.

---

### Cookie lifetime

| Option | Description | Selected |
|--------|-------------|----------|
| Long-lived — 90 days | Refreshed on each request; survives app restarts and iOS updates | ✓ |
| Session cookie | Gone when Safari fully quits; inconsistent iOS PWA behavior | |

**User's choice:** 90-day Max-Age, refreshed on each authenticated request.

---

## WebSocket auth

| Option | Description | Selected |
|--------|-------------|----------|
| Cookie auto-sent via rewrite | Remove ?token= from WS URL; browser sends cookie on same-origin upgrade | ✓ |
| Handshake token endpoint | GET /auth/ws-token returns short-lived JS-readable token for URL | |

**User's choice:** Cookie auto-sent — `createRealtimeClient()` removes token parameter.

---

### Client identity (household_id, member_id)

| Option | Description | Selected |
|--------|-------------|----------|
| GET /households/me on app load | Always-fresh fetch on mount; no local storage | ✓ |
| Non-HttpOnly companion cookie | Second JS-readable cookie for IDs | |
| Keep IDs in localStorage | IDs aren't secrets; re-fetch on eviction | |

**User's choice:** Fetch from server on mount via `GET /households/me`.

---

## Idempotent rejoin UX

| Option | Description | Selected |
|--------|-------------|----------|
| Silent idempotent join | POST /households/join returns existing token on name match; no UI change | ✓ |
| "Déjà membre ?" button on Welcome | Dedicated recovery entry point; more screens | |
| No recovery in this phase | Defer; user creates fresh account | |

**User's choice:** Silent idempotent join — existing Join flow IS the recovery flow.

---

### Join matching criterion

| Option | Description | Selected |
|--------|-------------|----------|
| Name match (case-insensitive) | Name only; color in request ignored for lookup | ✓ |
| Name + color match | Both must match; 409 if name matches but color differs | |

**User's choice:** Name match only (case-insensitive, trimmed).
