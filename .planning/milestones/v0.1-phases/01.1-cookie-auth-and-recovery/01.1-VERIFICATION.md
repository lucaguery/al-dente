### Human Verification Required

#### 1. iOS PWA Session Persistence

**Test:** Install the app as PWA on an iPhone via Safari → Add to Home Screen. Complete onboarding (create or join household). Force-quit the app (swipe up in app switcher). Wait a few seconds. Reopen.
**Expected:** App opens directly to home screen with full session intact — no redirect to `/onboarding/welcome`, household name and member name visible, settings screen shows invite code.
**Why human:** Requires a physical iPhone running Safari with iOS ITP active. The `aldente_auth` HttpOnly cookie persistence across PWA force-quit is the core goal of this phase and cannot be verified programmatically.

#### 2. Invite Code Copy on iOS Safari

**Test:** Navigate to `/settings`. Tap the copy icon next to the 6-char invite code.
**Expected:** Check icon appears, Sonner toast shows "Code copié !" (or the French `invite_code_copied` string), and the code is available on the clipboard.
**Why human:** `navigator.clipboard.writeText()` requires a user gesture and is subject to Safari's permission model. Cannot verify the clipboard grant in automation.

#### 3. Device-Wipe Recovery (Idempotent Rejoin)

**Test:** With two household members already onboarded, simulate device wipe on the second member's phone (or clear app data / use a fresh browser profile). Navigate to onboarding join flow, enter the invite code and the **same member name** (any case, any color).
**Expected:** App receives the original `member_id` (not a new UUID), the same session is restored, no duplicate member row in the DB.
**Why human:** Requires a two-device setup with a real Supabase DB to verify no duplicate row is inserted and the returned `member_id` matches the original.
