- [x] **ONBOARD-04**: User can join an existing household by entering an invite code, their name, and a color (`POST /households/join`) — *Validated: Phase 1, plans 01-04/01-06; idempotent rejoin added in Phase 01.1*

- [x] **RECIPE-05**: User can edit a recipe's fields and save changes (`PUT /recipes/{id}`) — *Validated: Phase 1, plans 01-08/01-11*
- [x] **RECIPE-06**: User can view a "Drafts inbox" tab labelled "À compléter (N)" listing all `status='draft'` recipes — *Validated: Phase 1, plans 01-08/01-10*

### LLM-Assisted Capture (CAPTURE) — 7/7

- [x] **CAPTURE-01**: User can capture a recipe via voice — Web Speech API records a French transcript, `POST /recipes/voice` creates a draft, FastAPI `BackgroundTask` promotes to `structured` via Gemini 2.5 Flash — *Validated: Phase 2, plans 02-01/02-02/02-04*
- [x] **CAPTURE-02**: User can capture a recipe via 1–4 photos — `POST /recipes/photo` (multipart) creates a draft, `BackgroundTask` runs Gemini multimodal extraction — *Validated: Phase 2, plans 02-01/02-02/02-04*
- [x] **CAPTURE-03**: User can paste a recipe URL — `POST /recipes/url` stores the URL in `source_capture`; URL fetch + extraction is productize-later — *Validated: Phase 2, plans 02-01/02-04*
- [x] **CAPTURE-04**: When a draft is promoted to `structured`, all connected clients in the household receive a `recipe.promoted` WebSocket event — *Validated: Phase 2, plan 02-01 (broadcast_to_household call in BackgroundTask)*
- [x] **CAPTURE-05**: User can voice-modify an existing recipe — `POST /recipes/{id}/voice-modify` returns Gemini-modified fields; the edit form opens pre-filled for review — *Validated: Phase 2, plans 02-02/02-05*
- [x] **CAPTURE-06**: Raw inputs (transcript / URL / photo paths) are persisted in `source_capture` JSONB on every recipe row, never discarded — *Validated: Phase 2, plans 02-01/02-02*
- [x] **CAPTURE-07**: Voice notes on the cooking-log finalization screen flow into the `notes` textarea via the OS keyboard mic affordance (in-app Web Speech disabled — broken on iOS PWA standalone). Helper copy `Tu peux dicter avec le micro du clavier.` directs users to the iOS keyboard mic. — *Validated: Phase 4, plan 04-02 (VoiceInput component wired to notes field)*

### Daily Shortlist (SHORTLIST) — 5/5

- [x] **SHORTLIST-01**: A daily shortlist of ≤ 5 recipes is generated automatically at 16:00 household-tz via APScheduler — *Validated: Phase 3, plan 03-01*
- [x] **SHORTLIST-02**: User can manually regenerate the shortlist with optional filters (cuisine, max_prep_time, exclude_protein, required_moods) via `POST /shortlists/regenerate` — *Validated: Phase 3, plans 03-01/03-02*
- [x] **SHORTLIST-03**: Scoring runs hard filters first, then soft scoring (seasonality + recency + mood overlap − recent-cuisine/protein penalty + 0–0.2 jitter) per SPEC.md §Algorithm — *Validated: Phase 3, plan 03-01 (`services/algorithm.py`)*
- [x] **SHORTLIST-04**: Diversification (`select_top5_with_diversity`) picks distinct cuisines and proteins where possible; cold-start tuning at `<10` / `10–29` / `30+` recipes — *Validated: Phase 3, plan 03-01*
- [x] **SHORTLIST-05**: User can view today's shortlist as a swipe deck (`framer-motion`) showing both members' votes per card — *Validated: Phase 3, plan 03-02*

### Voting (VOTE) — 5/5

- [x] **VOTE-01**: User can cast `yes` or `no` on each shortlist recipe; vote stored in `votes` keyed on `(shortlist_id, recipe_id, member_id)` — *Validated: Phase 3, plans 03-01/03-02*
- [x] **VOTE-02**: Voting state per recipe is computed from votes — Validé / Pressenti / Contesté / Rejeté / Sans avis. No `state` column. — *Validated: Phase 3, plan 03-01 (`compute_vote_state`)*
- [x] **VOTE-03**: A "Tu décides" button appends 5 `yes` votes for the requesting member (`POST /shortlists/{id}/delegate`); any partner `yes` becomes Validé — *Validated: Phase 3, plans 03-01/03-02*
- [x] **VOTE-04**: Veto window closes when the first `CookingLog` for the day is created — later `no` votes accepted (signal for v0.2 weighting) but cannot un-cook — *Validated: Phase 3, plan 03-01*
- [x] **VOTE-05**: All clients in the household receive `vote.created` WebSocket events within ~200ms of a vote being cast — *Validated: Phase 3, plans 03-01/03-02 (broadcast + DOM event bridge)*

### Cooking Log (COOK) — 5/5

- [x] **COOK-01**: User can tap "Je commence à cuisiner" on a Validé/Pressenti recipe — `POST /recipes/{id}/cook` creates an immutable `CookingLog` with `cooked_at = now()` — *Validated: Phase 3, plans 03-01/03-04*
- [x] **COOK-02**: An "En train de cuisiner" banner shows on home until the log is finalized or skipped — *Validated: Phase 3, plan 03-04; banner cleared via `cooking.finalized` WS event in Phase 4*
- [x] **COOK-03**: User can finalize the log later with photos (≤ 4), a 3-value rating (`loved`/`liked`/`disliked`), and free-text notes — `PUT /cooking-logs/{id}` — *Validated: Phase 4 UAT, 9/9 checks passed*
- [x] **COOK-04**: User can dictate notes via the OS keyboard dictation affordance directly into the notes textarea on the finalization screen — in-app Web Speech NOT used. Helper copy directs to iOS keyboard mic. — *Validated: Phase 4, plan 04-02 (VoiceInput wired to notes field)*
- [x] **COOK-05**: On log creation, `recipes.last_cooked_at` and `recipes.cook_count` update in the same DB transaction as the `cooking_logs` insert — *Validated: Phase 4, plan 04-01 (same SQLAlchemy session; `last_cooked_photo_path` also updated in same tx)*

### Realtime (REALTIME) — 3/3

- [x] **REALTIME-01**: Both clients subscribe to a household-scoped WebSocket channel after authenticating — *Validated: Phase 1, plan 01-05; cookie auth integrated in Phase 01.1*
- [x] **REALTIME-02**: WebSocket server broadcasts `recipe.created`, `recipe.promoted`, and `vote.created` events to all connected clients in the household — *Validated across Phases 1–4; extended to `cooking.started`, `cooking.finalized`, `recipe.deleted`, `recipe.updated`*
- [x] **REALTIME-03**: WebSocket client reconnects with exponential backoff on disconnect (Railway free-tier restart resilience) — *Validated: Phase 1, plan 01-07 (partysocket: 250ms → 5s, maxRetries=Infinity)*
