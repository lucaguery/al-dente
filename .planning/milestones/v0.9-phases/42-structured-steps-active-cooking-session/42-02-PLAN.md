<objective>
Extend the Gemini extraction schema so newly-promoted recipes ship `steps: list[StepEntry]` (where `StepEntry = {text, ingredient_refs}`) instead of the legacy `list[str] | None`. Update the extraction prompt to instruct Gemini to (a) emit the new structured shape and (b) reference ingredient names verbatim from its own extracted `ingredients[]`. Update `_apply_extracted` so persistence handles Pydantic-to-JSONB serialization correctly. Update `llm_fixtures.canned_thread_extract` so deterministic test mode emits the new shape. Add ≥2 tests covering the prompt clause and the end-to-end thread-LLM contract.

Critical refinement from 42-RESEARCH.md §R-03 + §landmines: The existing `_apply_extracted` line 397 does `recipe.steps = extracted.steps` which is fine when `extracted.steps` is `list[str]` but breaks under the new schema (Pydantic models cannot be persisted directly to a JSONB column — SQLAlchemy will try to JSON-encode them and fail). The fix is `recipe.steps = [s.model_dump(mode="json") for s in (extracted.steps or [])]`.

Per the locked-vocabulary discipline in CLAUDE.md, `StepEntry` is declared in TWO Python files: `app/schemas/recipe.py` (owned by 42-01) and `app/services/llm.py` (this plan). The mirror is intentional and documented; drift is a bug category.
</objective>
