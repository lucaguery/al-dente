## Overview

Al Dente v0.1 is a shared recipe + decision PWA for couples, built to eliminate the daily "on mange quoi ?" debate. It ships as an installable PWA (Safari → Add to Home Screen on both iPhones) with no App Store, no $99/year, no native build. The v0.1 definition of done is behavioral: ≥ 2 weeks of daily use by both household members at end of W4.

Four waves of work (Foundations → LLM Capture → Decide → Polish) delivered 49 requirements across 5 phases. Album (ALBUM-01/02/03) was cut to v2 per `04-CONTEXT.md` decision c7ee1f0 — not useful enough at couple-scale to justify the build cost in v0.1.

**Key technical choices that shaped the build:**

- Python FastAPI backend (Luca's AI-engineer stack; Gemini Python SDK is the reference impl)
- Same-origin HttpOnly cookies via Next.js `beforeFiles` rewrite proxy (Phase 01.1 urgent fix — iOS PWA force-quit evicted `localStorage`)
- Server-side `BackgroundTask` promotion pipeline (single source of truth; no device-vs-device race)
- Voting state computed from `votes` rows (no `state` column to drift)
- DOM CustomEvent bridge pattern for all WS → React updates (RealtimeProvider dispatches; page components listen)
- OS-keyboard-mic for voice notes (in-app Web Speech API dead on iOS PWA standalone)

### Phase 01.1: cookie-auth-and-recovery (INSERTED)

**Goal**: Migrate auth from `localStorage` bearer tokens (evicted on iOS Safari PWA force-quit) to same-origin HttpOnly cookies via a Next.js `beforeFiles` rewrite proxy. Add idempotent name-based rejoin so returning users don't repeat onboarding. Ship a `/settings` screen exposing the household invite code.
**Depends on**: Phase 1
**Driver**: Dual-phone testing revealed iOS Safari evicts `localStorage` across PWA force-quit → reopen, forcing onboarding repeat. Must land before Phase 2 dispatches because Phase 2's recipe routes need the final auth scheme.
**Plans**: 6 plans (01.1-01 through 01.1-06)

Plans:

- [x] 01.1-01: Context + architecture decision (rewrite proxy selected over Supabase Auth cookie)
- [x] 01.1-02: Backend `Set-Cookie: aldente_auth` + `GET /api/households/me` session endpoint
- [x] 01.1-03: Next.js `beforeFiles` rewrite proxy — `/api/*` → Railway, same-origin cookie forwarding
- [x] 01.1-04: `SessionProvider` + `useSession()` hook — replaces `localStorage` reads throughout app
- [x] 01.1-05: `OnboardingGuard` wrapping all protected routes — replaces ad-hoc token checks
- [x] 01.1-06: `/settings` route — household name + invite code (copy-to-clipboard) + member color dot

**Highlights:**
- `aldente_auth` cookie: `HttpOnly; Secure; SameSite=Lax; Path=/api; Max-Age=31536000`
- Backend validates cookie via `Depends(current_member)` — same FastAPI dependency, different extraction path
- Idempotent rejoin: `POST /households/join` with an existing name in the household returns the existing member's token rather than 409
- `OnboardingGuard` uses `useSession()` status field (`"loading"` / `"authenticated"` / `"unauthenticated"`) — no ad-hoc localStorage reads anywhere after Phase 01.1

**Goal**: Voice (Web Speech → backend → Gemini), photo (multipart → Gemini multimodal), and paste-URL surfaces all create drafts that promote to `status='structured'` via FastAPI `BackgroundTask`, with WebSocket `recipe.promoted` broadcast on status flip. Voice modification of existing recipes and a generic VoiceInput wrapper for cooking-log notes ship alongside.
**Depends on**: Phase 1 + Phase 01.1 (final auth scheme needed before capture routes)
**Requirements**: CAPTURE-01..07 (7 total)
**Plans**: 5 plans

Plans:

- [x] 02-01: Promotion pipeline backend — voice/photo/url routers + `BackgroundTask` + Alembic 0003 (promotion_attempts, promotion_error)
- [x] 02-02: Gemini 2.5 Flash integration — `services/llm.py` + voice/photo/voice-modify prompts + retry logic
- [x] 02-03: Phase 2 i18n strings + typed API helpers (`lib/recipes.ts` extended)
- [x] 02-04: Voice capture tab + photo capture tab + URL capture form — frontend UI surfaces
- [x] 02-05: RecipeDraftCard 3-variant rewrite (manual / processing / failed) + VoiceModifySheet + VoiceInput wrapper

**Highlights:**
- Single `POST /recipes/<surface>` shape for all 5 surfaces; backend returns `draft` immediately
- `BackgroundTask` runs Gemini extraction async; on success, flips `status='structured'`, broadcasts `recipe.promoted`

- `sessionStorage` one-shot bridge for voice-modify: VoiceModifySheet → serialized GeminiExtractedRecipe → edit form prefill → consumed and cleared on mount

## Milestone Summary

### Key Decisions

| Decision | Outcome |
|----------|---------|
| PWA + `next-pwa` over native iOS | ✅ Validated — $0/year, Safari install works on both iPhones |
| Python (FastAPI) backend over Node | ✅ Validated — Gemini Python SDK integration smooth |
| Invite-code auth over OAuth | ✅ Validated — simple enough for 2-person household |
| Same-origin cookie auth (Phase 01.1) | ✅ Validated — solves iOS force-quit session loss |
| Server-side `BackgroundTask` promotion | ✅ Validated — single source of truth, no race conditions |
| Voting state computed, not stored | ✅ Validated — no drift possible, derivation clean |
| Denormalized `last_cooked_at` + `cook_count` | ✅ Validated — same-tx update enforced by architecture |
