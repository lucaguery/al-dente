# Requirements: Al Dente — v0.3 Audit & Uniqueness Foundation

**Defined:** 2026-05-09
**Core Value:** Eliminate the daily "on mange quoi ?" debate via a shared library, async voting, and voice/photo capture — installable PWA on both iPhones with no App Store, no $99/year, no native build.

**Milestone goal:** Produce a grounded, evidence-backed assessment of Al Dente's current UX and design quality on a real production environment, so v0.4 can target what genuinely makes the app unique.

**Note on grammar:** This is an audit milestone. The "user" in `User can do X` is the operator (running the seed) or the auditor (Claude+MCP performing the walkthrough), not an end user of the app. Phrasing is kept user-centric where it reads naturally and switched to "Operator" / "Auditor" where forcing it would obscure intent.

## v1 Requirements

### SEED — Production Synthetic Household

- [x] **SEED-01**: Operator can run the seed CLI against prod Supabase and create/update a clearly-labeled synthetic household ("[SYNTHETIC] Démo Al Dente" or chosen label) without touching real user data.
- [x] **SEED-02**: Synthetic household is fully idempotent across re-runs — same UUIDs, same invite code, no duplicate-key errors, deterministic content. (Closes the SEED-01 cross-day hole carried from v0.2.2 backlog *for the prod synthetic specifically*.)
- [x] **SEED-03**: Seed CLI prints the synthetic household's invite code to stdout so the operator can join the synthetic env from their own phone.
- [x] **SEED-04**: Hard-refusal guard — seed refuses to run against prod unless an explicit opt-in flag or env var is set. A written runbook explains how to refresh and tear down.
- [x] **SEED-05**: Synthetic household coverage matches the local seed shape: 2 members + 21 recipes + 3 cooking logs + 7 votes covering all 5 computed states (Validé / Pressenti / Contesté / Rejeté / Sans avis).

### WALK — Exploratory Feature Walkthrough

- [x] **WALK-01**: Playwright MCP walkthrough exercises every shipped surface against the prod synthetic env: 5 capture surfaces (quick / full / voice / photo / url), shortlist, vote, cooking log, history, exports, push, realtime sync, onboarding, settings.
- [x] **WALK-02**: Walkthrough operates in exploratory mode — improvised inputs, unusual paths, weird states — explicitly designed to surface issues that scripted golden paths would miss.
- [x] **WALK-03**: Walkthrough output is a structured `WALKTHROUGH.md` with one section per surface, severity-tagged findings (blocker / friction / nit), and reproduction steps where applicable.
- [x] **WALK-04**: Blocker-severity findings are filed as GitHub issues with reproduction steps; friction / nit findings remain in `WALKTHROUGH.md` as input to the synthesis phase.

### AUDIT — Design Quality & Originality

- [x] **AUDIT-01**: Every screen reachable from the synthetic household is visited and scored under the existing `/gsd-ui-review` 6-pillar rubric.
- [x] **AUDIT-02**: Each surface receives a "feels generic vs feels Al Dente" originality judgment alongside its 6-pillar score, with concrete justification (specific elements that feel boilerplate vs. specific elements that feel earned).
- [x] **AUDIT-03**: Visual evidence (Playwright MCP screenshots) is captured for each scored surface and linked from the audit doc.
- [x] **AUDIT-04**: Output is per-surface UI-REVIEW files plus a milestone-level `UI-AUDIT.md` aggregating scores + originality judgments into a single readable summary.

### SYNTH — Synthesis & Handoff

- [x] **SYNTH-01**: A single `ASSESSMENT.md` document combines WALK findings + AUDIT scores into a ranked findings list, ordered by impact on the "feels Al Dente" question.
- [x] **SYNTH-02**: The assessment is descriptive, not prescriptive — surfaces opportunities and tradeoffs but does **not** propose v0.4 phases (clean separation between assessment and roadmap).
- [x] **SYNTH-03**: The assessment explicitly states what the next `/gsd-new-milestone` cycle should consume — i.e., names the inputs but stops short of dictating outputs.

## v2 Requirements

_None — v0.3 deliberately produces an assessment, not a forward roadmap. v0.4 requirements are defined later from `ASSESSMENT.md` via a fresh `/gsd-new-milestone` cycle._

## Out of Scope

| Feature | Reason |
|---------|--------|
| Fixing any issues found during WALK | Audit milestone — fixes are v0.4 territory or filed as separate v0.2.2 work. v0.3 surfaces, it does not repair. |
| Production seed for *real* users or multi-tenant fixtures | Single synthetic household only; expanding scope undermines the safety guarantees in SEED-04. |
| Cross-browser / cross-device audit | Locked to iPhone-shape Chromium (matches v0.2.1 Phase 10 viewport). Safari quirks are caught manually by the operator joining from their own iPhone. |
| v0.4 phase planning inside SYNTH | Explicit non-goal — clean handoff demands separation between "what we found" and "what we should do." |
| Scripted golden-path E2E expansion | v0.2.1 Phase 10 already covers that; v0.3 is exploratory by design. |
| Closing v0.2.2 backlog issues (Sheet-01 [#1], TZ-01, URL-01, CL-01, SEED-01 local, POLISH-01/02) | Tracked in `PROJECT.md` "Surfaced for follow-up". Out of v0.3 scope unless the audit re-discovers them with new severity, in which case the assessment notes the upgrade. |
