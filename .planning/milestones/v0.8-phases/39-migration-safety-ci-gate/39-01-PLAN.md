<objective>
Close MIG-01 + MIG-02: every Alembic migration in `backend/alembic/versions/` is exercised
through `upgrade <rev>` → `downgrade <prev>` on a freshly-created throwaway Postgres
database, proving the deploy contract documented in `backend/CLAUDE.md` (Railway runs
`alembic upgrade head` before each uvicorn restart) cannot silently break.

Purpose: protects against migration rot now that v0.8 is locking the test surface. A
broken `downgrade()` is invisible until a rollback is needed in prod — this plan makes
it a CI failure on the PR that introduces it.

Output: 3 new files under `backend/tests/migrations/` (package init, conftest with
throwaway-DB fixture + autouse seed override, parametrized migration test). No source
files under `backend/app/` are modified. No changes to the existing top-level
`backend/tests/conftest.py`.
</objective>
