    2. Create `scripts/check-enum-leak.sh` (executable, shebang `#!/usr/bin/env bash`, `set -euo pipefail`). The script:
       - Defines a regex union of the locked vocabulary tokens (see `<interfaces>` for the list; `american` and `other` deliberately excluded — `other` is a common English word, `american` is a common adjective).
       - Greps `frontend/app/` and `frontend/components/` for the union.
       - Excludes (via `--exclude` / explicit path filters): `frontend/lib/enums.ts`, `frontend/lib/enum-labels.ts`, anything under `frontend/tests/` or `frontend/**/*.spec.ts` or `frontend/**/*.test.ts`, anything under `frontend/.next/`, and the i18n file `frontend/lib/i18n/fr.json` (it MUST contain the keys — they're the mapping source).
       - Restricts matches to template literals (` `…` `) and JSX text positions to reduce false positives. Practical approach: grep for the token as a whole word (`-w`) and post-filter offenders that are inside an `import` line, comment, or matching one of the exclusion patterns. Trade-off acknowledged — the gate is intentionally conservative (favor false-positives surfaced for human review over silent re-leak).
       - On match: prints each offending file:line:content + a one-line `FAIL: enum-leak detected` summary + `exit 1`.
       - On no match: prints `OK: no enum-leak detected in frontend/{app,components}` and `exit 0`.

    3. Concrete script body (model — adjust regex tokens per the interface list):

       ```bash
       #!/usr/bin/env bash
       # Phase 35 ENUM-04 — repo-wide grep gate against raw locked-vocabulary
       # values leaking into user-facing frontend code. Mirrors v0.5 Phase 22 D-18
       # discipline. CI-runnable; non-zero exit blocks the build.
       #
       # Excludes the canonical translator surface (lib/enums.ts, lib/enum-labels.ts),
       # tests, .next build artifacts, and the i18n source file fr.json.

       set -euo pipefail

       cd "$(dirname "$0")/.."

       # Locked-vocab union — keep in sync with frontend/lib/enums.ts.
       # Deliberately excludes 'american' (common adjective) and 'other'
       # (common English word) to keep false-positive rate manageable.
       PATTERN='\b(italian|indian|mexican|french|asian|mediterranean|middleEastern|northAfrican|comfort|festive|fresh|easy|medium|hard|beef|chicken|fish|pork|spring|summer|autumn|winter)\b'

       EXCLUDES=(
         --exclude-dir=.next
         --exclude-dir=node_modules
         --exclude-dir=tests
         --exclude=enums.ts
         --exclude=enum-labels.ts
         --exclude=fr.json
         --exclude='*.spec.ts'
         --exclude='*.spec.tsx'
         --exclude='*.test.ts'
         --exclude='*.test.tsx'
       )

       OFFENDERS=$(grep -rnE "${EXCLUDES[@]}" "$PATTERN" frontend/app frontend/components 2>/dev/null || true)

       # Filter: drop import/from lines (legitimate enum-type imports + type names),
       # drop lines whose first non-whitespace char is '//' or '*' (comments),
       # drop lines that match a TypeScript type position (e.g. `: "italian" |`)
       # — favor recall over precision; a future tightening can adopt AST parsing.
       FILTERED=$(printf '%s\n' "$OFFENDERS" \
         | grep -v -E '^[^:]+:[0-9]+:\s*(import |from |//|\*|\s*\*)' \
         | grep -v -E ':[^:]*:\s*$' \
         || true)

       if [ -n "$FILTERED" ]; then
         echo "FAIL: enum-leak detected in frontend/{app,components}:"
         echo "$FILTERED"
         echo ""
         echo "Wrap raw enum keys via useEnumLabels() (see frontend/lib/enum-labels.ts)."
         echo "If an offender is a legitimate type literal or false-positive,"
         echo "narrow the regex or add a path/file exclusion above."
         exit 1
       fi

       echo "OK: no enum-leak detected in frontend/{app,components}"
       exit 0
       ```

    4. `chmod +x scripts/check-enum-leak.sh` after writing.

    5. Add an npm script in `frontend/package.json` so the gate is reachable via the standard `npm run` surface. Edit the `scripts` block; add:
       ```json
       "enum-leak-check": "bash ../scripts/check-enum-leak.sh"
       ```
       Place it after `"lint"` for proximity to other quality gates.

    6. Run the gate locally — it MUST exit 0 after Tasks 1+2 land (since those fix the three known leaks). If it exits non-zero, examine the offenders:

       - False positive (e.g. a type-literal position `: "italian" |` survived the filter)? Tighten the post-filter regex or add a targeted `--exclude=specific-file.ts`. Do NOT broaden the pattern to swallow it silently.

    7. Husky pre-commit wire-up is OUT OF SCOPE per CONTEXT deferred §1. The npm-script + bare bash invocation are enough for CI / manual runs in this phase.
