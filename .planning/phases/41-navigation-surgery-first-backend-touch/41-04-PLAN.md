# Plan 41-04: ShortlistThumbButtons 3-button refactor + undo wiring

## Goal

Ship UNDO-02 + UNDO-03 — the frontend half of the deck undo feature. Three-button stable-layout action bar (X / RotateCcw / Heart) on every shortlist card; the middle button is disabled when there's nothing to undo OR when the veto window has closed. Both disabled paths surface a preemptive tooltip explaining why. On successful undo, optimistic UI revert + backend DELETE; on 409 race-condition, sonner toast + cache refetch.

This plan is the Wave-2 dependent — it needs Plan 41-01's `DELETE /votes/{vote_id}` endpoint + extended POST-returns-vote_id contract to execute end-to-end. Plan 41-01 must merge first.

## Tasks

### Task 1: Add `deleteVote` to lib/votes.ts

Mirror the existing `postVote` shape. Function signature:

```ts
export async function deleteVote(voteId: string): Promise<void> {
  await api<void>(`/votes/${voteId}`, {
    method: "DELETE",
  });
}
```

The existing `api()` utility (lib/api.ts) handles the HttpOnly cookie auth (invariant #8) and 401 redirect. 409 throws as an Error with the response body's `detail` field — caller can `instanceof Error` + check the message to dispatch the race-condition toast.

If the existing api() utility doesn't expose 409 discrimination, extend it minimally: throw a custom `ApiError` class with a `status` property so callers can `if (e.status === 409) { ... }`.

### Task 3: Wire `canUndo` + `onUndo` in `ShortlistDeck`

In `frontend/components/ShortlistDeck.tsx`:

- Import `deleteVote` from `@/lib/votes`
- Add a `useCookingLogs(shortlist.date)` hook call (or use the existing hook if available — likely `useCookingLogs()` returns today's logs; planner verifies the hook signature)
- Compute `vetoWindowOpen = cookingLogs.length === 0` (no cooking_log finalized for today → undo allowed)
- Compute `currentMemberVote` from `votes` props: `votes.find(v => v.recipe_id === front.id && v.member_id === me.id)` — if present, the current member has voted on the front card
- Compute `canUndo = !!currentMemberVote && vetoWindowOpen && !voteInFlight`
- Compute `lockedTooltip = !vetoWindowOpen ? t("shortlist.undo.locked") : undefined`
- Add `onUndo` handler:
  ```ts
  async function handleUndo() {
    if (!currentMemberVote || !canUndo) return;
    setVoteInFlight(true);
    try {
      await deleteVote(currentMemberVote.id);
      // Optimistic: pop voteHistory + remove vote from votes prop via parent callback
      setVoteHistory((h) => h.slice(0, -1));
      onVoteApplied({ ...currentMemberVote, deleted: true } as any); // parent treats deleted: true as a remove
    } catch (e) {
      if (e instanceof Error && e.message.includes("409")) {
        toast(t("shortlist.undo.race_toast"));
        // Refetch cookingLogs to surface the new disabled state on next render
        await refetchCookingLogs();
      } else {
        toast.error(t("shortlist.undo.generic_error"));
      }
    } finally {
      setVoteInFlight(false);
    }
  }
  ```
- Pass `canUndo`, `handleUndo`, `lockedTooltip` to `<ShortlistThumbButtons />`
- The parent `onVoteApplied` callback (passed from the deck's parent) must accept a `deleted: true` payload to remove the vote from local state; coordinate this with the existing votes-state owner (likely HomeDecide). If `onVoteApplied` doesn't have a delete path, add one — same shape, one new field.

### Task 5: Add Playwright spec `frontend/tests/e2e/deck-undo.spec.ts`

   - Click Undo → assert sonner toast surfaces with race-condition copy

Use existing Playwright fixtures from `frontend/tests/e2e/`. The seed helper pattern (cooking_log direct insert) likely already exists for finalization tests — reuse it.
