<objective>
Close BUG-02 (gh#24): recipe SVG illustrations render as visible pictograms instead of muted empty squares.

Purpose: ET's default serializer invents `ns0:` prefixes when an XML doc declares a default namespace via `xmlns`. The sanitizer round-trips Gemini's SVG through ET, so its output looks like `<ns0:svg xmlns:ns0="…"><ns0:path …/></ns0:svg>` — perfectly valid XML but the browser cannot resolve it as inline SVG (it needs the SVG namespace as the default on the root). Result: every per-recipe illustration on `RecipeCard` + `RecipeDraftCard` rendered as an empty muted square. Fix in two layers (D-06): primary is `ET.register_namespace("", SVG_NS)` at module level (D-07) so ET emits bare `<svg>`; belt-and-suspenders is a regex strip of any residual `nsN:` prefixes. New unit tests pin the contract. Existing `ns0:`-poisoned rows in production get re-sanitized through the new pipeline via one idempotent Alembic data migration (D-09, D-10) that runs on next Railway deploy.

Output: Sanitizer emits browser-renderable SVG; all 28 existing security tests still pass + 3 new tests pin the no-prefix contract; production data heals on next deploy with zero manual steps.
</objective>
