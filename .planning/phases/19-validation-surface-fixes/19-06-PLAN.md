    ## Why this exists

    Web Push on iOS Safari PWA is fragile: the device must be installed-to-home-screen
    (`navigator.standalone === true`), the user must have granted permission via a
    user gesture, and the subscription must reach the household via `POST /push/subscribe`
    BEFORE any fan-out can land. The v0.3 audit (B-13) found that we shipped the
    mechanism in v0.1 Phase 03 but never deterministically observed an end-to-end
    delivery from product code → OS notification on BOTH household iPhones.

    Production paths to push delivery (`services/shortlist.generate_daily_shortlist` →
    `services/push.send_push_to_household` and the partner-cooking-started broadcast)
    are non-deterministic: shortlist generation is a 16:00 household-tz cron, and
    partner-cooking-started requires the partner to actually tap Finaliser. Neither is
    operator-controllable in a single test session.

    The admin-test endpoint (plan 19-03) gives the operator a deterministic, on-demand
    fire-test scoped to a single member. This document records the observed round-trip
    using that endpoint.

    ## Pre-flight checklist

    Before running the round-trip, the operator confirms:

    - [ ] Backend dev server up: `cd backend && uv run uvicorn app.main:app --reload`
    - [ ] Frontend dev server up: `cd frontend && npm run dev`
    - [ ] Both iPhones have the PWA installed to home screen (`navigator.standalone === true`)
    - [ ] Both iPhones are signed in via aldente_auth cookie (test against `/api/auth/whoami` if uncertain)
    - [ ] `NEXT_PUBLIC_VAPID_PUBLIC_KEY` is set in the frontend env (matches backend `VAPID_PUBLIC_KEY`)
    - [ ] `VAPID_PRIVATE_KEY` + `VAPID_EMAIL` are set in the backend env
    - [ ] Each iPhone has granted notification permission AT LEAST ONCE in the current session
      (verifiable: `Notification.permission === "granted"` in the dev console attached to the iPhone)
    - [ ] Each iPhone shows a row in the `push_subscriptions` table for its member

    ## Round-trip procedure

    1. **iPhone A — fire from /styleguide:**
       - Navigate to `https://<dev-host>/styleguide`
       - Scroll to the "Push (dev only)" section at the bottom
       - Tap "Tester le Web Push"
       - Expected: toast on the page "Test envoyé : 1 notification(s) (0 échec(s))"
       - Expected: within ~5s, OS notification on iPhone A — title "Test al dente", body "Notification de test depuis /styleguide"

    2. **iPhone A — verify no realtime broadcast:**
       - Open Safari devtools (Inspector via Mac) attached to the PWA's webview
       - Network tab: confirm only one HTTP entry during the fire — `POST /api/push/test`
       - WebSocket frames: confirm NO `recipe.*` / `vote.*` / `cooking_log.*` / `member.*` frames during the test
       - This proves D-19-11 / CLAUDE.md invariant #4 carve-out is honored

    3. **iPhone B — repeat:**
       - Sign in iPhone B as the partner member
       - Same fire procedure on iPhone B's `/styleguide`
       - Expected: iPhone B receives ITS OWN notification; iPhone A does NOT receive iPhone B's test
       - This proves the member-scoping (T-19-03-06)

    4. **Cross-device safety check:**
       - From iPhone A's `/styleguide`, fire the test
       - Confirm iPhone B does NOT receive the notification (only A's member's subscriptions are fanned out)
