## Trust Boundaries

No new boundaries — this plan only modifies presentational JSX within an existing client component. The voice tab continues to POST a free-text transcript via the existing `postVoiceCapture` helper (cookie-auth, same-origin). No new client-emitted events, no new external integrations.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04-01 | Tampering (XSS) | Callout headline renders `t("idle_helper")` from i18n | accept | i18n value is a static French string controlled by the codebase; React JSX auto-escapes regardless. No `dangerouslySetInnerHTML`. |
| T-06-04-02 | Information disclosure / privacy | Voice transcript submitted as free text | accept | Inherited Phase 2 disposition: transcript travels over HTTPS via cookie-auth; backend stores in `source_capture` JSONB (which is intentionally retained — see CLAUDE.md "Raw inputs are kept forever"). No new exposure. |
| T-06-04-03 | Spoofing | iOS keyboard-mic transcription | accept | Inherited Phase 2 disposition: OS-level dictation is opaque to the app; user controls the mic. No new attack surface. |

No high-severity threats. ASVS L1 not applicable to a presentational re-theme. The D-Voice deviation lock (no `webkitSpeechRecognition`) is itself a long-standing security/privacy posture: by NOT capturing audio in-app, the app avoids the entire microphone-permission attack surface.
