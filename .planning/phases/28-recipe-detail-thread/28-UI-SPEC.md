# Phase 28 — UI Design Contract
## Recipe-detail thread

> Visual and interaction contract for the four NEW visual surfaces Phase 28 introduces on top of
> the Phase 27 chat shell: the « épinglé » / « conflit » Caveat marginalia label, the « Valider »
> primary CTA inside question bubbles, the collapsed-advisory muted summary line, and the
> in-flight syncing marker. Generated by gsd-ui-researcher.

---

## SCOPE BOUNDARY — what this spec covers

Phase 28 is a wiring phase. The chat layout, system bubble shell, state pill, composer, and
BottomNav are **locked by 27-UI-SPEC.md** — this document does NOT re-specify them.

The four new surfaces this spec owns:

| Surface | Files touched |
|---------|---------------|
| 1. « épinglé » / « conflit » Caveat marginalia | `RecipeForm.tsx` (per-input) + `page.tsx` (section-level) |
| 2. « Valider » primary CTA in question bubble | `SystemBubble.tsx` (question branch) |
| 3. Collapsed advisory muted line | `SystemBubble.tsx` (advisory branch) |
| 4. In-flight syncing marker | `SystemBubble.tsx` (Valider + advisory CTAs) |

## Spacing Scale

Inherited from 27-UI-SPEC.md. No new spacing values. The four new surfaces map to existing
tokens as follows:

| Token | Value | Phase 28 usage |
|-------|-------|----------------|
| xs | 4px | Gap between label text and « épinglé » marginalia inline |
| sm | 8px | Valider button margin-top inside question bubble; advisory collapsed line vertical padding |
| md | 16px | Inherited (composer, section padding) |
| lg | 24px | `--spacing-page-x` — horizontal page padding; marginalia absolute-position offset reference |

**Marginalia positioning exception:** The detail-page section-level marginalia is
`position: absolute; left: -4px; transform: translateX(-100%); top: 2px` relative to the
section header wrapper (`position: relative`). This overflows the 24px `--spacing-page-x`
safe zone by up to ~50px (the width of the Caveat label). The parent `<div>` at
`px-(--spacing-page-x)` must carry `overflow: visible` to allow this overflow. On the 390px
iPhone viewport the gutter between the screen edge and the content column is exactly 24px —
the label fits without clipping against the safe-area boundary.

**Alternative for edit form:** The edit form marginalia is `display: inline` immediately after
the `<Label>` element (to its right), separated by a 4px gap. No absolute positioning required
on the edit form — labels have horizontal space to the right of their text.

## Typography

Inherits all four type roles from 27-UI-SPEC.md. Phase 28 adds one role: **Marginalia-pin**.

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Body | IBM Plex Sans | 14px | 400 | 1.45 | (inherited) |
| Caption | IBM Plex Sans | 13px | 400 | 1.5 | Advisory collapsed muted line; stepper unit label |
| Label-small | IBM Plex Sans | 10px | 600 | 1.0 | (inherited — sys-head, state pills) |
| Thread-meta title | Cormorant Garamond | 13px | 600 | 1.2 | (inherited) |
| **Marginalia-pin** | **Caveat** | **12px** | **500** | **1.0** | « épinglé » and « conflit » labels only |
| Valider button | IBM Plex Sans | 13px | 600 | 1.0 | Same register as existing advisory CTAs (h-9) |

**Marginalia-pin notes:**

- 12px is below the design system's smallest `.marginalia-sm` (1rem = 16px). Use an arbitrary
  Tailwind value or inline `fontSize: "12px"` — do NOT define a new design-system token for
  this sub-register. Rationale: the pin label is an aside, not a primary content role;
  keeping it sub-body reinforces the "margin annotation" metaphor.
- Weight 500 is an exception to the Phase 27 "only 400 and 600" rule. Caveat is a display
  handwritten font; at 12px, weight 400 is visually too thin and weight 600 too bold. Weight
  500 splits the difference for legibility. This exception applies ONLY to the Caveat
  marginalia labels.
- Slant: apply `transform: rotate(-1.2deg); display: inline-block` on detail-page gutter
  labels (the cookbook visual gesture). SKIP the slant on edit-form inline labels — at 12px
  the rotation adds visual noise in a dense label row.

## Color

Inherits the 60/30/10 split from 27-UI-SPEC.md. Phase 28 introduces no new palette tokens
but **assigns new semantic purposes** to two existing tokens.

| Role | Token | Light value | Phase 28 usage |
|------|-------|-------------|----------------|
| Dominant (60%) | `var(--background)` | `oklch(0.975 0.006 75)` | (inherited) |
| Secondary (30%) | `var(--card)` | `oklch(0.99 0.005 75)` | (inherited) |
| Accent (10%) | `var(--primary)` | `oklch(0.50 0.10 32)` terracotta | **« épinglé » marginalia label color** — extends the existing sys-head + state-pill usage; pin signal is a system affordance sharing the primary register |
| Destructive | `var(--destructive)` | `oklch(0.50 0.15 25)` | **« conflit » marginalia label color** — extends the existing « Échec » pill usage; conflit is a destructive escalation of the pinned state |
| Muted foreground | `var(--muted-foreground)` | `oklch(0.50 0.012 55)` | Advisory collapsed summary line; stepper unit label; syncing marker opacity target |

**Accent (`var(--primary)`) reserved for this phase:** user bubble fill (inherited), mic/send
button (inherited), Enregistrer CTA (inherited), sys-head label (inherited), state-pill borders
(inherited), active BottomNav tab (inherited), focus ring (inherited), **« épinglé »
marginalia label**, **« Valider » button background**.

**`var(--destructive)` reserved for:** validation errors (inherited), « Échec » pill
(inherited), **« conflit » marginalia label and its aria-pressed/tap affordance**.

### Syncing marker color rule

During in-flight POSTs (D-21), the tapped element dims using opacity, NOT a color token
change. Concrete values:

- Valider button in-flight: `opacity: 0.7` on the button text; the button background stays
  `var(--primary)`. A 12×12px Lucide `Loader2` spinner (animated `animate-spin`) replaces
  the button text. If Tailwind's `animate-spin` is not available on the Loader2 icon, use
  `className="animate-spin"`.
- Advisory CTA in-flight: both CTAs dim to `opacity: 0.5`. The tapped CTA shows the spinner
  in place of its text; the untapped CTA dims but retains its text (user cannot tap either
  during the in-flight window).

## Layout

### 1. Detail page — section-level marginalia (D-03)

Each section header wrapper in `/recipes/[id]/page.tsx` gains `position: relative` when any
field in its coverage group is pinned. The `<PinLabel>` mounts as a sibling element to the
`<h2>` (or the hero title `<h1>`), positioned via `position: absolute`.

```
section wrapper: position: relative; overflow: visible
  ↳ <h1> or <h2> section header (existing text)
  ↳ <PinLabel>  ← NEW, absolute-positioned in left gutter
      position: absolute; left: -4px; transform: translateX(-100%); top: 2px
      font-family: var(--font-marginalia); font-size: 12px; font-weight: 500
      color: var(--primary)   [épinglé] or var(--destructive) [conflit]
      transform: translateX(-100%) rotate(-1.2deg)
      display: inline-block; line-height: 1; white-space: nowrap
```

**Section-to-AnswerField coverage map** (locked in `frontend/lib/pin-sections.ts`):

| Detail page section | AnswerField keys covered |
|---------------------|--------------------------|
| Hero title `<h1>` | `title` |
| Description (if rendered) | `description` |
| Metadata pill row | `cuisine`, `mood`, `main_protein` |
| Prep/servings span | `prep_time_minutes`, `cook_time_minutes`, `servings`, `difficulty` |
| Ingredients `<h2>` | `ingredients` |
| Steps `<h2>` | `steps` |
| Seasonality (not currently rendered) | `seasonality` — skip per D-05 until section exists |
| Tags (not currently rendered) | `tags` — skip per D-05 until section exists |

Render condition: `isPinned = manuallyEditedFields.some(f => SECTION_FIELDS.includes(f))`.
Single `<PinLabel>` per section even if multiple fields in that section are pinned.

### 2. Edit form — per-input marginalia (D-04)

Each of the 11 labeled inputs in `RecipeForm.tsx` wraps its `<Label>` in an inline flex row:

```
<div className="flex items-center gap-1">
  <Label htmlFor="rf-{field}">{labelText}</Label>
  {manuallyEditedFields?.includes(fieldKey) && (
    <PinLabel field={fieldKey} hasConflict={...} onConflictTap={...} />
  )}
</div>
```

No absolute positioning on the edit form. The marginalia renders inline to the right of the
label text. Slant is NOT applied on the edit form (see §Typography).

Fields covered (11): `title`, `description`, `ingredients`, `steps`, `prep_time_minutes`,
`cook_time_minutes`, `difficulty`, `servings`, `cuisine`, `mood`, `main_protein`.

Fields excluded from edit-form marginalia (D-04): `seasonality` and `tags` (even though both
have form inputs in `RecipeForm.tsx` — the CONTEXT.md D-04 decision explicitly excludes them).

**« conflit » on the edit form:** The edit page (`/recipes/[id]/edit`) is a standalone route
that does NOT fetch `turns[]`. Therefore the edit form renders only « épinglé » (never
« conflit »). The « conflit » escalation is **detail-page-only** — only `/recipes/[id]/page.tsx`
has access to `turns[]` to compute open advisories. This is a deliberate scope decision
(28-RESEARCH.md §8).

### 3. Question bubble — Valider CTA layout (D-15)

The `<PinLabel>` Valider button appends BELOW the chip/stepper/text input row inside the
existing `<div className="flex flex-col gap-2">` of the question bubble. The bubble shell
(`max-w-[90%]`, `rounded-[18px_18px_18px_4px]`, `p-3`) is unchanged.

```
question bubble (existing shell)
  ↳ SysHead (existing)
  ↳ chip row OR stepper OR text input (existing, now interactive)
  ↳ Valider button (NEW — rendered below inputs, mt-2)
      className: PRIMARY_CTA_CLASS (existing: "flex-1 h-9 rounded-[10px] bg-primary
        text-primary-foreground font-semibold text-[13px] border-0 cursor-pointer")
      disabled when: no selection (chip), value=0 for servings (stepper),
                     empty string (text input), or committing=true
      in-flight: shows Loader2 spinner, button dims to opacity-70
```

The Valider does NOT take `flex-1` when it is the sole button. Use `w-full` instead, matching
the full bubble width.

### 4. Advisory bubble — collapsed state layout (D-19)

When `resolution` prop is non-null, the full advisory bubble shell is replaced by a single-line
muted element. No shell border, no padding, no sys-head — just the resolution text:

```
<div className="self-start px-3 py-1 text-[13px] text-muted-foreground italic">
  {t("advisory_resolved", { field, from, to, status })}
</div>
```

Alignment: `align-self: flex-start` (matches system-sender convention). No bubble shell —
this is a whisper line, not a card.

## Component Specifications

### `<PinLabel>` component

Location: `frontend/components/RecipeThread/PinLabel.tsx` (extracted component, usable from
both `page.tsx` sections and `RecipeForm.tsx`).

```tsx
interface PinLabelProps {
  field: AnswerField;
  hasConflict: boolean;
  onConflictTap?: () => void;
}
```

**Epinglé state** (`hasConflict === false`):

```tsx
<span
  style={{
    fontFamily: "var(--font-marginalia)",
    fontSize: "12px",
    fontWeight: 500,
    lineHeight: 1,
    color: "var(--primary)",
    display: "inline-block",
    // slant applied only on detail page via prop or wrapping class
  }}
  aria-label={undefined}  // purely decorative; surrounding label provides context
>
  {t("recipes.pin.label")}   {/* « épinglé » */}
</span>
```

**Conflit state** (`hasConflict === true`):

```tsx
<button
  type="button"
  style={{
    fontFamily: "var(--font-marginalia)",
    fontSize: "12px",
    fontWeight: 500,
    lineHeight: 1,
    color: "var(--destructive)",
    display: "inline-block",
    background: "none",
    border: "none",
    padding: 0,
    cursor: "pointer",
  }}
  onClick={onConflictTap}
  aria-label={t("recipes.pin.conflict_aria", { field: fieldLabel })}
>
  {t("recipes.pin.conflict")}  {/* « conflit » */}
</button>
```

Tap behavior on « conflit »: `scrollIntoView({ behavior: 'smooth', block: 'center' })` on the
advisory bubble element in the thread. The orchestrator passes this as `onConflictTap`.

**Slant wrapper** (detail page only): The section wrapper applies
`data-gutter-label` on the `<PinLabel>` and the CSS applies the rotate via:
```css
[data-gutter-label] { transform: rotate(-1.2deg); }
```
Or inline: pass a `gutter?: boolean` prop; when true, add `style={{ transform: "rotate(-1.2deg)" }}`.

### `<SystemBubble>` — question branch additions

New local state:

```tsx
const [selected, setSelected] = useState<string | string[] | number>(
  inputType === "stepper" ? 0 : multi ? [] : ""
);
const [committing, setCommitting] = useState(false);
```

Chip selected style (applied when chip value is in `selected`):
```
bg-primary text-primary-foreground border-primary border-[1.5px]
```

Unselected chip style (existing Phase 27 classes, now active):
```
border-[1.5px] border-border rounded-full px-4 py-2 text-[13px] font-semibold
text-foreground bg-background
```

Stepper: remove `disabled` from `+` / `−` buttons. Floor logic:
- `−` disabled when `selected === 0`
- For `servings`: Valider disabled when `selected === 0` (but `−` allowed down to 0 for display)
- For time fields: Valider enabled at 0

**Valider button classes** (reuses `PRIMARY_CTA_CLASS` with `w-full` override):
```
w-full h-9 rounded-[10px] bg-primary text-primary-foreground font-semibold text-[13px]
border-0 cursor-pointer disabled:opacity-50 disabled:cursor-not-allowed
```

### `<SystemBubble>` — advisory branch additions

Two new states in the advisory render branch:

**Collapsed resolution** (when `resolution` prop is `'accepted'` or `'dismissed'`):
The full bubble body (sys-head, value row, reason, CTAs) is replaced by the single-line
collapsed element from §Layout §4. No wrapper div, no shadow, no border.

**CTA syncing state** (`committing === true`):
Both CTAs dim to `opacity-50`. The tapped CTA text replaced by:
```tsx
<Loader2 size={14} className="animate-spin" aria-hidden />
```
Both buttons gain `disabled` attribute during `committing`.

## Motion Contract

Inherits all motion from 27-UI-SPEC.md (`variants.slideUp`, `AnimatePresence`, `transitions.fast`).
Phase 28 adds no new motion tokens.

### New motion applications

| Interaction | Motion | Values |
|-------------|--------|--------|
| Pin marginalia appear (optimistic on Valider tap) | No animation — instant render | React conditional render; no `AnimatePresence` wrapper (post-MVP per deferred ideas) |
| Pin marginalia disappear (on accept → unpin) | No animation — instant render | Same — post-MVP |
| Advisory collapse to muted line | No animation — instant re-render | The `resolution` prop change triggers a React re-render; no transition |
| Valider in-flight spinner | CSS `animate-spin` | Tailwind `animate-spin` class on `<Loader2>` — 360deg rotation, 1s linear infinite |
| Advisory CTA dimming | CSS `opacity` transition | `opacity: 1 → 0.5; transition: opacity 150ms var(--ease-craft)` |

Rationale for no entrance/exit animation on pin labels: the CONTEXT.md deferred section
explicitly defers "pin signal animation on entrance/exit" to post-MVP. The React conditional
render is instantaneous and consistent with how other inline state signals appear in the form.

### Copywriting rules

**« épinglé » vs « conflit »:** These are the only two states. There is no "pinned and
resolved" label — once an advisory is accepted (field unpin) or dismissed (field stays pinned,
advisory collapses), the marginalia returns to « épinglé » or disappears respectively. The
transition between the two states is instantaneous on user action (optimistic).

**Advisory collapsed copy:** The ICU pattern `{field} : {from} → {to} ({status})` uses the
`field()` method from `useEnumLabels()` to produce the French field label (e.g.
`cuisine : italien → méditerranéen (accepté)`). The `from` and `to` values are the raw string
representations of the advisory payload values — no enum translation for these, as they
represent user-visible recipe field values.

**Stepper unit placement:** The unit label (`« min »` or `« 2 pers. »`) renders AFTER the
stepper value span: `[−] [45] min [+]`. Implemented as a `<span>` between the stepper pill
and the right edge, styled as `text-[13px] text-muted-foreground ml-2`.

**Error toast consistency:** `action_failed` (Phase 28) coexists with `turn_failed` (Phase 27)
as separate keys. `turn_failed` covers network-layer failures on the text/voice/url/photo POST
path (connection error). `action_failed` covers semantic failures on the answer/proposal POST
path (validation, server error). The planner may merge them in the same commit if the copy is
identical in the final implementation — this spec preserves them as distinct to match CONTEXT.md
D-22.

**« Valider » friction rationale:** The Valider CTA in question bubbles uses the same h-9 /
rounded-[10px] / bg-primary shell as the advisory « Mettre à jour » CTA (from Phase 27
PRIMARY_CTA_CLASS). This is intentional — both are "commit an interpretation" gestures in the
same primary register. The user learns one pattern: "primary button = send to LLM or apply."
