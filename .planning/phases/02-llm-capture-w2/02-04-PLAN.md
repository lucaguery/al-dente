## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → frontend state | Untrusted; mitigated by client-side trim/length checks and backend re-validation. |
| File picker → frontend File state | OS-mediated; magic-byte sniff happens server-side (Phase 1 carry-over). |
| Frontend → /api/recipes/{voice,photo,url} | Cookie-authed via `credentials: include`; same-origin via Vercel rewrite. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04-01 | Information disclosure | Object URLs leak across mounts | mitigate | `useEffect` cleanup calls `URL.revokeObjectURL` on every preview URL when files change or component unmounts. |
| T-02-04-02 | Denial of service | Oversized photo batch hits Gemini | mitigate | Client-side 18 MB total cap (matches backend) + per-file UI feedback. Backend is the authoritative gate (Plan 02 Task 2). |
| T-02-04-03 | Tampering | URL field accepts any string | mitigate | Client-side `new URL(...)` parse + `http(s)` scheme check; backend re-validates the prefix and rejects with 422. |
| T-02-04-04 | Tampering | Voice transcript could embed prompt-injection text | mitigate | Backend (Plan 01) passes transcript as a separate `contents[]` element with structured-output schema; the locked-vocabulary Literal types constrain Gemini's output. |
| T-02-04-05 | Information disclosure | Hardcoded French would leak roadmap details | accept | All strings via `next-intl`; PWA-04 enforced by ESLint pass and acceptance criteria. |

</threat_model>
