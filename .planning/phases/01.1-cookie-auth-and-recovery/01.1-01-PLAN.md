<objective>
Migrate backend auth from "Authorization: Bearer only" to "cookie OR Bearer (dual-mode)" so iOS PWA sessions survive Safari's localStorage eviction. The cookie path is the new primary; Bearer remains as fallback for `curl`/Postman dev flows and the in-rollout transition window.

Purpose: iOS Safari ITP evicts `localStorage` on PWA force-quit → reopen, killing user sessions. HttpOnly same-origin cookies are not subject to this eviction and survive PWA restarts indefinitely (Max-Age=90d sliding refresh).

Output: `auth.py` exposes `current_member` (dual-mode), `set_auth_cookie(response, token)`, `clear_auth_cookie(response)`, and `AUTH_COOKIE_NAME = "aldente_auth"`. `households.py` POST routes mint cookie alongside `auth_token` in body. `ws.py` reads token from `websocket.cookies` first, query string second. New `auth_session.py` router exposes `DELETE /auth/session` for client-initiated logout.
</objective>

```python
import secrets
from fastapi import Cookie, Depends, Header, HTTPException, Response, status
from sqlalchemy import select
from sqlalchemy.orm import Session
from app.db import get_db

AUTH_COOKIE_NAME = "aldente_auth"
AUTH_COOKIE_MAX_AGE = 7776000  # 90 days


def generate_auth_token() -> str:
    return secrets.token_urlsafe(32)


def set_auth_cookie(response: Response, token: str) -> None:
    """Attach the aldente_auth cookie with locked attributes to the response.

    D-02: HttpOnly + Secure + SameSite=Strict + Path=/ + Max-Age=90d. Backend
    is the only writer; HttpOnly means JS cannot read or modify it.
    """
    response.set_cookie(
        key=AUTH_COOKIE_NAME,
        value=token,
        max_age=AUTH_COOKIE_MAX_AGE,
        path="/",
        secure=True,
        httponly=True,
        samesite="strict",
    )


def clear_auth_cookie(response: Response) -> None:
    """Emit Set-Cookie that expires aldente_auth immediately (logout)."""
    response.delete_cookie(key=AUTH_COOKIE_NAME, path="/")


def _extract_token(
    aldente_auth: str | None,
    authorization: str | None,
) -> str:
    """Cookie wins; Bearer header is the fallback (D-03)."""
    if aldente_auth:
        token = aldente_auth.strip()
        if token:
            return token
    if authorization and authorization.lower().startswith("bearer "):
        token = authorization.split(" ", 1)[1].strip()
        if token:
            return token
    raise HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="missing auth",
    )


def current_member(
    aldente_auth: str | None = Cookie(default=None, alias=AUTH_COOKIE_NAME),
    authorization: str | None = Header(default=None),
    db: Session = Depends(get_db),
):
    """Return the Member matching cookie OR Bearer token, else 401."""
    from app.models.member import Member  # noqa: PLC0415

    token = _extract_token(aldente_auth, authorization)
    member = db.scalar(select(Member).where(Member.auth_token == token))
    if member is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="invalid token",
        )
    return member
```

- DO NOT add Bearer rotation/expiry — D-03 says no expiry on the Bearer path in v0.1.
- Keep `generate_auth_token()` byte-for-byte (it is imported by `households.py`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Vercel rewrite → Railway | Untrusted user input (recipe names, invite codes) crosses here. The cookie travels in this same channel. |
| WS upgrade request → backend | Starlette parses cookies from upgrade headers; same trust level as HTTP. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.1-01-01 | Spoofing | aldente_auth cookie | mitigate | HttpOnly blocks JS read; Secure forces HTTPS; SameSite=Strict blocks CSRF cross-origin sends. Verbatim attribute string enforced via grep in acceptance_criteria. |
| T-01.1-01-02 | Tampering | Bearer fallback path | accept | D-03 documents the dual-mode tradeoff for dev. Bearer tokens have no expiry in v0.1; productize-later (V2-AUTH-01) replaces with Supabase Auth. |
| T-01.1-01-03 | Information Disclosure | WS upgrade with `?token=` | accept | Existing T-01-07-03 (productize-later) — token in query string still leaks to access logs in the fallback path. Cookie path is the new primary and does not leak. |
| T-01.1-01-04 | Denial of Service | DELETE /auth/session unauthenticated | accept | Endpoint has no DB write; idempotent cookie clear. Anonymous flood at most clears cookies that don't exist. Worth keeping unauth so a corrupted cookie can still be cleared. |
| T-01.1-01-05 | Elevation of Privilege | Cookie + Bearer race when both supplied | mitigate | Cookie wins (deterministic precedence in `_extract_token`); a stale Bearer header cannot override a fresh cookie. |
| T-01.1-01-06 | Repudiation | Logout audit trail | accept | Couple-scale; no compliance need for logout audit. |
| T-01.1-01-07 | Tampering | CSRF on credentialed POST /households | mitigate | SameSite=Strict on the cookie blocks cross-origin form-submit attacks. Same-origin via Vercel rewrite means no cross-origin attack surface in production. |
</threat_model>
