# Phase 01.1 Plan 06: Settings Screen Summary

Read-only `/settings` route exposing household name, invite code (monospaced + copy-to-clipboard), and current member name + color dot via `useSession()`, with all French strings in a new `settings.*` i18n namespace.

## What Was Built

**`frontend/app/settings/page.tsx`** — Three-block read-only screen:
1. Household name (from `session.household_name`)
2. Invite code — `text-[28px] font-mono tracking-[0.3em]` mirroring `onboarding/share-code` styling; Copy→Check icon swap + Sonner toast on click; `navigator.clipboard.writeText(session.invite_code)`
3. Current member name + `<MemberDot colorHex={...} />` color dot

Loading state renders a pulse skeleton. Unauthenticated state returns null (OnboardingGuard is the primary defense per T-01.1-06-03).

**`frontend/lib/i18n/fr.json`** — New `settings` namespace with 9 keys: `title`, `household_name_label`, `invite_code_label`, `invite_code_aria`, `invite_code_copy_aria`, `invite_code_copied`, `invite_code_copy_failed`, `invite_code_helper`, `member_label`.

**`frontend/components/BottomNav.tsx`** — Already had `{ href: "/settings", segment: "settings", icon: MoreHorizontal, labelKey: "more" }`. No code change.
