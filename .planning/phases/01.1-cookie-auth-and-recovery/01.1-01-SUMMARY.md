# Phase 01.1 Plan 01: Cookie Auth Migration (Backend) Summary

**One-liner:** HttpOnly same-origin cookie (`aldente_auth`) with dual-mode Bearer fallback — iOS Safari PWA sessions survive force-quit restarts.

## What Was Built

### Cookie attribute string (verbatim)

The locked attribute string `aldente_auth=<token>; HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=7776000` is emitted by `set_auth_cookie()` in `backend/app/auth.py` via FastAPI/Starlette's `response.set_cookie()`:

```python
response.set_cookie(
    key=AUTH_COOKIE_NAME,   # "aldente_auth"
    value=token,
    max_age=AUTH_COOKIE_MAX_AGE,  # 7776000 (90 days)
    path="/",
    secure=True,
    httponly=True,
    samesite="strict",
)
```

Files that emit it: `backend/app/routers/households.py` (POST /households, POST /households/join) via `set_auth_cookie()` call.

### Dual-mode precedence rule

Cookie wins. `_extract_token()` in `auth.py` checks `aldente_auth` cookie first; falls back to `Authorization: Bearer` header only if the cookie is absent or empty. A stale Bearer header in dev tooling cannot override a fresh server-set cookie (T-01.1-01-05 mitigation, D-03).

Error behavior:
- Neither present → `401 {"detail": "missing auth"}`
- Token present but no matching Member row → `401 {"detail": "invalid token"}`

### New routes

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| DELETE | /auth/session | None | Clear `aldente_auth` cookie. Idempotent, always 200. |

### CORS allow_credentials change

Changed `allow_credentials=False` → `allow_credentials=True` in `app/main.py`. Rationale: local dev runs frontend on `:3000` and backend on `:8000`; the `aldente_auth` cookie cannot travel cross-origin without this flag. Production uses Vercel rewrites so API calls are same-origin and credentials are same-origin by definition — no security regression in production.

### WebSocket cookie-first (D-05 backend half)

`ws.py` now reads `websocket.cookies.get(AUTH_COOKIE_NAME)` immediately after `await websocket.accept()` and uses that value as the token if present. The existing `?token=` query parameter remains as fallback. Both 1008 close paths and the registry contract are preserved unchanged.
