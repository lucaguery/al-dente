**One-liner:** Server-authoritative identity via `SessionProvider` — `GET /api/households/me` on mount replaces all `localStorage` reads; `RealtimeProvider` and `OnboardingGuard` now gate on cookie session status.

## What Was Built

### Backend: SessionResponse schema

`GET /households/me` now returns `SessionResponse` (new schema in `household.py`) instead of `HouseholdPublic`:

```json
{
  "household_id": "uuid",
  "household_name": "string",
  "invite_code": "string",
  "me": { "id": "uuid", "name": "string", "color_hex": "string", "joined_at": "..." },
  "members": [...]
}
```

`HouseholdPublic` is kept for backward compatibility (no other route used it yet).

### Frontend: SessionProvider

`frontend/components/SessionProvider.tsx` — new component:
- `SESSION_CHANGED_EVENT = "aldente:session-changed"` — event for same-tab refresh triggers
- Types: `SessionMember`, `SessionData`, `SessionStatus`, `SessionContextValue`
- Module-level singleton store + `useSyncExternalStore` (SSR-safe, no hydration mismatch)
- `fetchSession()` calls `GET /api/households/me`; sets `authenticated` or `unauthenticated`
- `SessionProvider` component: mounts fetch on boot, listens for `SESSION_CHANGED_EVENT`
- `useSession()` hook: returns `{ status, session, refresh }`

### Frontend: layout

`SessionProvider` wraps `RealtimeProvider` so the Realtime layer can consume `useSession()`.

### Frontend: lib/auth.ts

Reduced to:
- Re-export `SESSION_CHANGED_EVENT` from `SessionProvider`
- `clearLegacyLocalStorage()` — wipes `auth_token`/`household_id`/`member_id` from localStorage
- `AUTH_TOKEN_CHANGED_EVENT` alias (deprecated, one-release backward compat)
- All `saveAuthToken`, `getAuthToken`, `clearAuth`, `hasOnboarded` exports removed

### Frontend: OnboardingGuard

Replaced `hasOnboarded()/useSyncExternalStore` with `useSession()`. Redirects on `status === "unauthenticated"`, gates render on `status === "authenticated"`.

### Frontend: RealtimeProvider

- Removed `openedFor` token-keyed cache and `getAuthToken()` call
- Removed `AUTH_TOKEN_CHANGED_EVENT` window event listener
- `ensureOpen()` takes no arguments — calls `createRealtimeClient()` (no token)
- `useEffect` depends on `[status]` — WS opens only when `status === "authenticated"`

### Frontend: Onboarding pages

Both `create/page.tsx` and `join/page.tsx`:
- Import `useSession` instead of `saveAuthToken`
- Add `const { refresh } = useSession()`
- Replace `saveAuthToken(...)` with `await refresh()`
- Fix API paths: `/households` → `/api/households`, `/households/join` → `/api/households/join`, `/households/by-code/...` → `/api/households/by-code/...`

## Deviations from Plan

None — plan executed exactly as written.

The `void res` line in `join/page.tsx` was added to satisfy TypeScript's unused-variable check while preserving the `JoinResponse` type for forward compat. This is a minor stylistic addition, not a behavioral change.

## Known Stubs

None. All flows are wired end-to-end:
- `SessionProvider` fetches real identity from `GET /api/households/me`
- `OnboardingGuard` gates on server-confirmed session
- `RealtimeProvider` opens WS on confirmed authentication
- Onboarding pages refresh session after backend cookie is set

## Threat Flags

No new threat surface beyond what was modeled in the plan's `<threat_model>`.

T-01.1-05-03 (localStorage shadow state) is mitigated: `clearLegacyLocalStorage` is exported from `lib/auth.ts` and called by `lib/api.ts` on 401. The `auth_token`/`household_id`/`member_id` keys are evicted on the first 401 response.
