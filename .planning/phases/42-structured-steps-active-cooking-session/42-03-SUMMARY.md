# Plan 42-03 SUMMARY — POST /recipes/{id}/extract-steps + lazy backfill BackgroundTask

## What was built

The lazy-backfill endpoint + BackgroundTask that lets the frontend trigger structured-step extraction on first `/active` visit for recipes whose `steps` is empty or in the legacy flat-string shape.

- `POST /recipes/{recipe_id}/extract-steps` route in `app/routers/recipes.py` — uses `Depends(current_member)` for auth (invariant #8 HttpOnly cookie), `BackgroundTasks` to schedule the work (invariant #1 — never inline Gemini), and a small `ExtractStepsResponse` Pydantic DTO declared inline.
  - 202 Accepted `{recipe_id, scheduled: true, reason: null}` when steps need backfill.
  - 200 OK `{recipe_id, scheduled: false, reason: "already_extracted"}` when `_steps_are_structured(recipe.steps)` returns True.
  - 404 (NOT 403) for cross-household and recipe-not-found — leak prevention per T-01-08-04.
  - 401 unauthorized via the auth dependency.
- `extract_and_persist_steps` async coroutine in `app/services/llm.py` — mirrors the v0.6 `extract_and_process_url_turn` BackgroundTask pattern. Opens its own SessionLocal, defensively re-checks the idempotency guard, reads turn-0 (immutable per invariant #5), and delegates to the existing `_run_thread_llm` which:
  - builds the full-thread Gemini prompt (now with the 42-02 ingredient_refs clause),
  - calls Gemini (or canned fixture in test mode),
  - applies non-pinned-conflicting fields via `_apply_extracted` (42-02 StepEntry persistence path),
  - emits summary/question/advisory turns,
  - commits, and
  - **broadcasts `recipe.updated`** to the household (invariant #4).
- `_steps_are_structured` helper — `False` for `None`, `[]`, or any legacy `list[str]` entries; `True` only when every entry is a dict with `text` + `ingredient_refs` keys.
- `llm_service` module-level import in the router so tests can `monkeypatch.setattr("app.services.llm.extract_and_persist_steps", fake)` and have the BackgroundTask scheduler pick up the patched callable.
- Six tests in `backend/tests/test_router_recipes_extract_steps.py`:
  - `test_extract_steps_unauthorized_returns_401`
  - `test_extract_steps_cross_household_returns_404` (asserts no household_id leak in body)
  - `test_extract_steps_recipe_not_found_returns_404`
  - `test_extract_steps_empty_steps_returns_202_and_schedules_task` (asserts BackgroundTask scheduled with correct args)
  - `test_extract_steps_already_structured_returns_200_idempotent` (asserts no scheduling)
  - `test_extract_steps_broadcasts_recipe_updated_after_commit` (invariant #4 — fires after commit; payload carries StepEntry-shaped dicts)
- One test in new `backend/tests/test_invariants.py`:
  - `test_extract_and_persist_steps_preserves_turn_zero_payload` — invariant #5 regression guard; deep-copy of turn-0 payload before, asserts equality after, and confirms steps DID change so the test wasn't a silent no-op.

## Deviations from Plan

**[Rule 0 — Plan sketch signature differs from real `_run_thread_llm`]** Plan sketch called `_run_thread_llm(thread_payload)` synchronously with a hand-built dict; real signature is `async def _run_thread_llm(db, recipe, trigger_turn_id)`. Adapted by making `extract_and_persist_steps` itself `async`, opening its own SessionLocal, looking up the recipe + turn-0, and awaiting `_run_thread_llm` directly. This is strictly cleaner — `_run_thread_llm` already owns `_apply_extracted` (42-02 StepEntry persistence) AND the `recipe.updated` broadcast, so no duplication. Skipped the plan's `_build_steps_extraction_payload` helper — it would have duplicated `_build_thread_prompt`'s work.

**[Rule 1 — Bug surfaced beyond plan]** First commit attempt blocked by ruff E402 because `import asyncio` was added mid-file in the test. Moved it to the top-of-file import block.

**[Rule 0 — `llm_service` module import in the router]** Added a module-level `from app.services import llm as llm_service` so the route can dereference `llm_service.extract_and_persist_steps` at call time. Without this, monkeypatching the function symbol after the router was imported would not affect the BackgroundTask scheduler. The plan called for `from-import`; the from-import is still there for `_steps_are_structured` (which is referenced before BackgroundTask scheduling and doesn't need late-binding), but the BackgroundTask itself goes through the module.

**Total deviations:** 3 (signature adaptation + ruff E402 fix + module-late-binding for monkeypatch). **Impact:** none — all 7 tests + adjacent suites green; the BackgroundTask contract is identical to what the plan intended; the OpenAPI gate auto-regenerated docs cleanly.
