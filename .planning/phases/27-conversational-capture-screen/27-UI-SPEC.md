## Spacing Scale

Declared values (all multiples of 4). Token names map to the `--spacing-*` CSS custom properties already in the design system.

| Token | Value | Usage in Phase 27 |
|-------|-------|-------------------|
| xs | 4px | Icon gaps inside bubbles; bubble waveform bar gap |
| sm | 8px | Bubble internal vertical padding (voice/text); save-bar top padding; thread-meta padding |
| md | 16px | Default element spacing; composer horizontal padding; sheet item gap |
| lg | 24px | Section padding `--spacing-page-x` (1.5rem = 24px); sheet content vertical padding |
| xl | 32px | Layout gaps — not primary in this phase |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- **Composer bottom padding**: `8px + env(safe-area-inset-bottom)` — required for iOS home-indicator clearance (source: mockup `.composer` CSS).
- **Touch targets for + and mic/send buttons**: 36px diameter minimum (9×4 grid unit, per mockup). The mic button when used as primary CTA is 36×36px. Not 44px because the `send-bar` above the composer provides the dominant full-width 44px save CTA.
- **Chat body horizontal padding**: 14px (mockup `padding: 14px 14px 8px`) — not a multiple of 4. Token this as `chat-x: 14px` (new token request — see §New Token Requests below).
- **Bubble vertical inter-gap**: 10px (`gap: 10px` in `.chat-body`). Not a multiple of 4. Token as `bubble-gap: 10px` (new token request).
- **Thread-meta padding**: `8px 14px` — uses the same 14px horizontal as the chat body for alignment continuity.

## Motion Contract

All motion values sourced from `frontend/lib/motion.ts` — no new tokens introduced.

| Interaction | Variant / Transition | Values |
|-------------|---------------------|--------|
| New bubble append (user or system) | `variants.slideUp` + `AnimatePresence` | `y: 12 → 0; opacity: 0 → 1; duration: 0.28s; ease: easeCraft [0.32, 0.72, 0, 1]` |
| Mic→send icon morph | `variants.fadeIn` | `opacity: 0 → 1; duration: 0.15s; ease: easeCraft` |
| Save bar appear (0 bubbles → 1 bubble) | `variants.slideUp` | `y: 12 → 0; opacity: 0 → 1; duration: 0.28s` |
| Sheet open/close | Radix default (`data-open:slide-in-from-bottom-10`) | ~200ms — already in `SheetContent` className |
| Save button disabled→enabled | CSS `opacity` transition | `150ms var(--ease-craft)` |
| Bubble dismiss (X tap) | `AnimatePresence` exit: `variants.fadeIn` reversed | `opacity: 1 → 0; duration: 0.15s` |

`AnimatePresence` wraps the bubble list in `chat-body` with `mode="popLayout"` so that removal of a pending bubble causes surrounding bubbles to shift smoothly.

## Claude's Discretion Resolutions

These items were flagged as undecided in `27-CONTEXT.md §Claude's Discretion`. They are resolved here as part of the visual/interaction contract.

### Pre-save bubble mutability
**Decision:** Yes — each pending bubble has a dismiss (X) tap target. No reorder. No edit-in-place (type a new bubble instead). The X button is a 20px circle at `position: absolute; top: -6px; right: -6px` relative to the bubble wrapper. The bubble wrapper has `position: relative; overflow: visible`.

### Pre-save persistence
**Decision:** No — pending state is ephemeral in Phase 27. A `// TODO(productize)` comment is added inline in the Composer state initialization. If a user closes the page they re-capture from scratch.

### Cancel / back behavior with pending bubbles
**Decision:** If `pendingBubbles.length >= 1` and the user taps the back arrow, show a native `window.confirm()` dialog (not a custom modal — simpler, no focus-trap issues) with the `recipes.thread.discard_confirm` copy. If confirmed, clear state and `router.back()`. Rationale: `window.confirm()` is universally accessible and avoids another Sheet/Dialog component for a low-frequency destructive action.

Alternative considered: shadcn `AlertDialog` — rejected for Phase 27 simplicity. Phase 28 can upgrade if the design requires more visual control.

### Loader / extraction-in-progress UX
**Decision:** A small italic centered text row (the "extraction-in-progress row" specified above) appears in the `chat-body` below the last user turn immediately after save. It shows `recipes.thread.extracting` = « Extraction en cours… ». It is removed when either:
1. `recipe.promoted` WebSocket event fires (Phase 25 contract — status flips to `structured`).
2. The first `summary` system turn arrives via `turn.created` (Phase 29 contract).

No skeleton bubble alternative — the italic row is lighter, matches the `draft_title_placeholder` copy register, and doesn't reserve vertical space for unknown content.

### Photo-bytes cap surfacing
**Decision:** The `18 MB total cap` (T-02-04-02) is enforced in the composer state as a running total across all photo pending bubbles. When a new photo would push the total over 18 MB, a `toast.error(t("recipes.thread.photo_cap_exceeded"))` fires and the photo is not added. The count is also gated at 4 photos maximum (matches `PhotoCaptureTab` T-02-04-02 cap). Both checks happen before the pending bubble is created, not at save time.

### RecipeListPage behavior post-/inbox deletion
**Decision:** The main `/recipes` list fetches `structured` + `failed` together. The `?status=draft` API filter is preserved server-side but not rendered in the frontend. `status='draft'` recipes surface briefly on `/recipes/[id]` during the promotion window (the thread-meta strip shows the draft state pill). No separate filter chip for failed recipes in Phase 27 — the « Échec » pill on the card is the only surface.
