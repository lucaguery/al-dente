<objective>
Build the shared, reusable `RecipeThread` component directory — the same instance Plan 27-03 mounts on `/recipes/new` (capture mode) and Plan 27-05 mounts on `/recipes/[id]` (detail mode). CAPTURE-04: one component, two mount points.

This plan is **pure new files plus i18n additions** — zero conflicts with the demolition plan (27-03). The component is **props-driven**: state ownership and API calls live in the parent page (Plan 27-03's `/recipes/new/page.tsx` for capture mode; Plan 27-05's `/recipes/[id]/page.tsx` for detail mode). This makes the component reusable and the save/POST flow testable without React-tree mocking.

Component boundary — explicit:
- **State that lives IN `RecipeThread/Composer.tsx`**: the textarea content (`text` local state for the morph button) and which sheet is open. Nothing else.
- **State that lives IN the parent page**: the array of pending bubbles (capture mode), the array of persisted turns (detail mode), the saving flag, the recipeId, the photo total-bytes running total. The component receives them via props and emits events via callbacks.
- This lift-up is what makes Plan 27-03 (save flow) testable and Plan 27-05 (detail mount) re-use the same component without state-clash.

Out-of-scope (renders STUBS only — Phase 28 wires handlers):
- `question` turn chips/steppers — render visually per UI-SPEC.md but have no `onClick` / `onChange` handler (visual-only).
- `advisory` turn « Mettre à jour » / « Ignorer la suggestion » CTAs — render visually but `disabled={true}` or `onClick` is a no-op.
- `summary` turn CTAs (« Oui, compléter » / « Plus tard ») — same treatment.

Out-of-scope (Phase 29 emits these turns):
- The component does NOT emit `summary` / `question` / `advisory` turns. It RENDERS them when they arrive via props.

Purpose: Plan 27-03 needs a `<RecipeThread mode="capture" />` it can drop into the rewritten `/recipes/new/page.tsx`. Plan 27-05 needs the same component with `mode="detail"` and `recipeId={id}` for the detail page. Phase 28 will add real handlers to the question/advisory stubs by editing the same files.

Output: A 9-file component directory + ~30 new French i18n keys. No page imports it yet — that happens in Plans 27-03 and 27-05.
