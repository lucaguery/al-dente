**Why Wave 3:** depends on Plan 01 (backend), Plan 02 (frontend), and Plan 03 (lint + ROADMAP). Cannot start UAT before all three have deployed.

**Setup:** ensure both iPhones have the latest deployed PWA installed via Safari → Share → Add to Home Screen. If either device shows the old stub, force-quit Safari + the PWA, then reopen the home-screen icon to pick up the new service-worker.

**Section 1 — End-to-end cooking-log loop (two phones)**

1. **Phone A** (you): from Home, tap a Validé recipe and "Je commence à cuisiner" — confirm the "En train de cuisiner" banner appears.
2. **Phone B** (partner): confirm the SAME banner appears on their Home within ~5s (cooking.started realtime echo, existing Phase-3 behavior).
3. **Phone A**: tap "Finaliser" on the banner. Confirm the finalize page opens and shows: page title "Finaliser la cuisson", recipe title in « guillemets », empty Photos section, "Comment c'était ?" rating section with helper "Choisis une note pour pouvoir finaliser.", Notes section.
4. **Phone A**: confirm the "Finaliser" button at the bottom is **disabled** (greyed out, cursor-not-allowed). Tap it — nothing should happen.
5. **Phone A**: tap the photo-add tile, choose Camera, snap a photo. Confirm it appears in the grid. Repeat for a second photo (max 4 allowed).
6. **Phone A**: tap "Adoré" — confirm the card becomes rose-tinted with a filled Heart icon and a brand-rose border.
7. **Phone A**: tap the Notes textarea. Tap the iOS keyboard mic icon (the bottom-row mic on the iOS keyboard). Speak: « C'était parfait, on en remange demain. ». Confirm the text appears in the textarea.
8. **Phone A**: tap "Finaliser". Confirm: (a) the app navigates back to Home (`/`), (b) a soft toast `Bien enregistré.` appears, (c) the cooking banner is gone.
9. **Phone A**: navigate to /recipes. Confirm the recipe you just cooked shows the **photo you just took** as its primary thumbnail (NOT the static recipe photo). This is the D-05 living-image moment.
10. **Phone B**: navigate to /recipes (or refresh if already there). Confirm the same recipe shows the SAME living-image thumbnail. This proves the recipe.updated realtime broadcast works.
11. **Phone A**: tap into the recipe detail — confirm `last_cooked_at` shows "il y a quelques secondes" and `cook_count` is incremented by 1.

**Section 2 — Mobile a11y polish (D-08)**

Run on **Phone A**:
12. From Home, navigate to the finalize page (start a new cooking session OR re-use the Phase-3 banner if active). On the finalize page:
13. Tap each rating card in turn. Each tap target should be comfortably finger-sized (≥ 48px high). Confirm.
14. Tap the photo-add tile. Confirm it's a clear visual target (≥ 48px).
15. **Optional, on a desktop with Chrome DevTools mobile emulation:** Tab through the page with the keyboard. Confirm: each rating card shows a visible rose-colored ring on focus; the Finaliser button shows a ring; the textarea shows a ring; the photo-add tile shows a ring.
16. **Optional, contrast check:** tap each rating card to select it. Take a screenshot of the selected state. Run a contrast checker (e.g., webaim.org/resources/contrastchecker/) on the selected text vs background — Adoré card text/bg should pass WCAG AA, same for Bien (emerald) and Passable (neutral).

**Section 3 — Offline app shell (D-07)**

17. On **Phone A** with the PWA closed: enable Airplane Mode in iOS Settings.
18. Open the PWA. Confirm the app shell renders — the bottom nav appears, Home loads (likely shows a loading or empty state for shortlist data — that's expected without network).
19. Tap /recipes — confirm the route navigates (the cached shell is responsive).
20. API endpoints should NOT crash the app — they should show loading or empty / error states gracefully.
21. Disable Airplane Mode. Wait ~10s. Confirm the WebSocket "reconnecting…" indicator (Phase 1) appears briefly then clears, and data starts loading again.

**Section 4 — Sanity smoke**

22. Run the swipe deck on Home (if a shortlist exists) — confirm the cards still swipe smoothly. (Verifies D-09 ShortlistCard refactor didn't regress motion.)
23. macOS: System Preferences → Accessibility → Display → "Reduce motion" ON. Reload the app on a device that picks up the OS setting. Confirm the swipe deck no longer animates the rotation. Toggle off.

**What to watch for (failure modes):**
- Photo grid never loads → check the cooking-log signed-URL endpoint
- Finaliser button stays enabled with no rating → client-side gate broken
- Rating selected state shows wrong color → token mapping regressed
- Living-image thumbnail does NOT appear after finalization → check that Plan 01 broadcasts recipe.updated AND that RecipeCard's path-prefix branch routes to getCookingLogSignedPhotoUrl
- Toast appears BEFORE navigation (toast on the finalize page, not Home) → check ordering in CookingLogFinalize.tsx handleSubmit (router.push must come before toast.success)
- Voice notes: iOS keyboard mic doesn't start — that's an iOS setting issue (Settings → General → Keyboard → Enable Dictation), not a v0.1 bug
