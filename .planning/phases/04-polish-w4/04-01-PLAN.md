<objective>
Backend support for cooking-log finalization (COOK-03) and the same-transaction denormalized recipe update (COOK-05). Adds:

1. A new nullable column `recipes.last_cooked_photo_path TEXT` (Alembic 0005) so the recipe card can show the most recent cooking-log photo as its primary image (D-05).
2. A `PUT /cooking-logs/{id}` endpoint that accepts `{photo_paths, rating, notes}`, finalizes the log, and in the SAME DB TRANSACTION updates `recipes.last_cooked_at`, `recipes.cook_count`, and `recipes.last_cooked_photo_path` (= `photo_paths[0] if photo_paths else NULL`). Architecture invariant #3 from CLAUDE.md.
3. A `POST /cooking-logs/{id}/photos` endpoint that mirrors the existing `POST /recipes/{id}/photos`, uploading to Supabase Storage under a `cooking-logs/{household_id}/{log_id}/` prefix and appending the path to `cooking_logs.photo_paths`.
4. Two WebSocket broadcasts: `cooking.finalized` (closes the partner's CookingBanner in real-time) and `recipe.updated` with the updated recipe (so the partner's RecipeCard living-image refreshes via the existing Phase-1 handler with no new frontend code).

Purpose: This is the single backend prerequisite for Plan 02 (finalize page UI) — Plan 02 cannot wire the form without these endpoints and the new field. By landing both endpoints + migration in one wave-1 plan, frontend and lint plans run unblocked.

**Important refactor of Step C:** capture the "was unfinalized" flag BEFORE mutating `log_row.rating`. Final code:

```python
@router.put(
    "/cooking-logs/{log_id}",
    response_model=CookingLogResponse,
)
async def finalize_cooking_log(
    log_id: UUID,
    body: CookingLogFinalizeRequest,
    member: Member = Depends(current_member),
    db: Session = Depends(get_db),
):
    log_row = db.scalar(
        select(CookingLog).where(
            CookingLog.id == log_id,
            CookingLog.household_id == member.household_id,
        )
    )
    if log_row is None:
        raise HTTPException(404, "cooking log not found")

    persisted = set(log_row.photo_paths or [])
    proposed = list(body.photo_paths)
    for p in proposed:
        if p not in persisted:
            raise HTTPException(
                status_code=422,
                detail="photo_paths must be a subset of paths uploaded to this log",
            )

    is_first_finalize = log_row.rating is None

    log_row.photo_paths = proposed
    log_row.rating = body.rating
    log_row.notes = body.notes

    # Denormalized update on the parent recipe (COOK-05). Same transaction.
    new_photo_path = proposed[0] if proposed else None
    recipe_values: dict = {
        "last_cooked_at": log_row.cooked_at,
        "last_cooked_photo_path": new_photo_path,
    }
    if is_first_finalize:
        recipe_values["cook_count"] = Recipe.cook_count + 1

    db.execute(
        update(Recipe)
        .where(Recipe.id == log_row.recipe_id)
        .values(**recipe_values)
    )
    db.commit()
    db.refresh(log_row)

    # Reload recipe to broadcast the latest shape (FE living-image uses this)
    recipe = db.get(Recipe, log_row.recipe_id)
    if recipe is not None:
        await broadcast_to_household(
            member.household_id,
            "recipe.updated",
            RecipeResponse.model_validate(recipe).model_dump(mode="json"),
        )
    await broadcast_to_household(
        member.household_id,
        "cooking.finalized",
        {
            "log_id": str(log_row.id),
            "recipe_id": str(log_row.recipe_id),
            "rating": str(log_row.rating.value) if log_row.rating else None,
        },
    )

    return CookingLogResponse.model_validate(log_row)
```

The `recipe.updated` broadcast piggybacks on the existing Phase-1 contract — `RecipeDetailPage` already invalidates on this event, so the partner's recipe-card living image refreshes with no new frontend code.

**WHY same transaction:** CLAUDE.md architecture invariant #3 says "Denormalized fields on `recipes`: `last_cooked_at` and `cook_count` are updated in the same DB transaction as `cooking_logs` insertion. Don't compute on read." Phase 4 extends this to also include `last_cooked_photo_path`. We use a single `db.commit()` after both the log mutation AND the `update(Recipe).where(...).values(...)` — SQLAlchemy keeps both in one transaction.

**Idempotency note:** if a client re-PUTs an already-finalized log (re-finalize case mentioned in CONTEXT.md `<decisions>`), `is_first_finalize` is False so `cook_count` is NOT incremented. `last_cooked_at` is set to `log_row.cooked_at` (unchanged), and `last_cooked_photo_path` re-derives from the new photo set. This preserves the cook-count invariant even though the v0.1 frontend gates re-finalize.

def upload_cooking_log_photo(
    *,
    household_id: UUID,
    log_id: UUID,
    content: bytes,
) -> str:
    """Validate, generate a server-side filename, upload, return the storage path.

    Mirrors :func:`upload_recipe_photo` but writes to a different prefix so
    cooking-log photos and recipe photos do not collide. Same bucket
    (recipe-photos) — couple-scale storage; productize-later if we ever
    need a separate bucket for retention policies.

    Returns the bucket-relative path:
        ``cooking-logs/{household_id}/{log_id}/{uuid}.{ext}``
    """
    if len(content) > MAX_BYTES:
        raise ValueError("oversize")
    sniffed = detect_mime_and_ext(content)
    if sniffed is None:
        raise ValueError("unsupported")
    mime, ext = sniffed

    path = f"cooking-logs/{household_id}/{log_id}/{uuid4()}.{ext}"

    client = _supabase()
    try:
        client.storage.from_(BUCKET).upload(
            path=path,
            file=content,
            file_options={"content-type": mime, "upsert": "false"},
        )
    except Exception as exc:  # noqa: BLE001
        log.exception(
            "supabase upload failed (cooking_log) path=%s err=%s", path, exc,
        )
        raise
    log.info(
        "cooking_log_photo.uploaded household=%s log=%s path=%s bytes=%d",
        household_id, log_id, path, len(content),
    )
    return path

from app.services.storage import (

MAX_PHOTOS_PER_COOKING_LOG = 4  # SPEC.md: photo_paths ≤ 4 (mirror recipe rule)


@router.post(
    "/cooking-logs/{log_id}/photos",
    response_model=CookingLogResponse,
    status_code=status.HTTP_201_CREATED,
)
async def upload_cooking_log_photo_endpoint(
    log_id: UUID,
    file: UploadFile = File(...),
    member: Member = Depends(current_member),
    db: Session = Depends(get_db),
) -> CookingLogResponse:
    """Append a photo to a cooking log. Same threat model as
    backend/app/routers/photos.py:
      - 404 (not 403) on cross-household — does not leak existence
      - magic-byte MIME sniff (T-01-09-01)
      - server-side path (T-01-09-02)
      - 8 MiB hard cap (T-01-09-03)
    """
    log_row = db.scalar(
        select(CookingLog).where(
            CookingLog.id == log_id,
            CookingLog.household_id == member.household_id,
        )
    )
    if log_row is None:
        raise HTTPException(404, "cooking log not found")

    current_paths = list(log_row.photo_paths or [])
    if len(current_paths) >= MAX_PHOTOS_PER_COOKING_LOG:
        raise HTTPException(
            status_code=status.HTTP_409_CONFLICT, detail="photo limit reached"
        )

    content = await file.read(MAX_BYTES + 1)
    if len(content) > MAX_BYTES:
        raise HTTPException(
            status_code=status.HTTP_413_REQUEST_ENTITY_TOO_LARGE,
            detail=f"file exceeds {MAX_BYTES} bytes",
        )
    if not content:
        raise HTTPException(400, "empty upload")

    try:
        path = upload_cooking_log_photo(
            household_id=member.household_id,
            log_id=log_row.id,
            content=content,
        )
    except ValueError as exc:
        if str(exc) == "oversize":
            raise HTTPException(
                status_code=status.HTTP_413_REQUEST_ENTITY_TOO_LARGE,
                detail="oversize",
            ) from exc
        if str(exc) == "unsupported":
            raise HTTPException(
                status_code=status.HTTP_415_UNSUPPORTED_MEDIA_TYPE,
                detail="unsupported media",
            ) from exc
        raise

    log_row.photo_paths = current_paths + [path]
    db.commit()
    db.refresh(log_row)

    return CookingLogResponse.model_validate(log_row)


@router.get("/cooking-logs/{log_id}/photo-url")
def cooking_log_signed_photo_url(
    log_id: UUID,
    path: str = Query(..., min_length=1, max_length=300),
    member: Member = Depends(current_member),
    db: Session = Depends(get_db),
) -> dict:
    """Mirror of GET /recipes/{id}/photo-url. T-01-10-01: validate path is
    on this log to prevent minting URLs for arbitrary bucket objects.
    """
    log_row = db.scalar(
        select(CookingLog).where(
            CookingLog.id == log_id,
            CookingLog.household_id == member.household_id,
        )
    )
    if log_row is None:
        raise HTTPException(404, "cooking log not found")
    if path not in (log_row.photo_paths or []):
        raise HTTPException(404, "path not on cooking log")
    url = create_signed_photo_url(path)
    return {"url": url, "expires_in": SIGNED_URL_TTL_SECONDS}
