# D-04 Verification — gsd-docs-update at non-root paths

**Date:** 2026-05-18
**Outcome:** FAIL

## Method invoked

Method (b) — direct CLI invocation of the underlying handler.

The `gsd-docs-update` user-facing path runs through `node $HOME/.claude/get-shit-done/bin/gsd-tools.cjs generate-claude-md` (and a sibling `generate-claude-profile`). That handler is the only refresh path that touches `<!-- GSD:* -->` marker blocks on disk; everything else routes through it.

Exact commands run from the repo root:

```bash
# 1. Plant a probe block in each scoped file.
#    backend/CLAUDE.md:
#      <!-- GSD:stack-start source:codebase/STACK.md -->
#      ## Technology Stack — probe
#      PROBE-MARKER-7733 ...
#      <!-- GSD:stack-end -->
#    frontend/CLAUDE.md:
#      <!-- GSD:conventions-start source:CONVENTIONS.md -->
#      ## Conventions — probe
#      PROBE-MARKER-7733 ...
#      <!-- GSD:conventions-end -->

# 2. Invoke the refresh handler against each non-root path.
node $HOME/.claude/get-shit-done/bin/gsd-tools.cjs generate-claude-md \
  --output backend/CLAUDE.md --auto
# → "Generated 5/6 sections. Skipped (manually edited): stack."

node $HOME/.claude/get-shit-done/bin/gsd-tools.cjs generate-claude-md \
  --output frontend/CLAUDE.md --auto
# → "Generated 5/6 sections. Skipped (manually edited): conventions."

# 3. Verify probe survival.
grep -c "PROBE-MARKER-7733" backend/CLAUDE.md frontend/CLAUDE.md
# → backend/CLAUDE.md:1
# → frontend/CLAUDE.md:1
```

Source inspection (`profile-output.cjs::cmdGenerateClaudeMd`, lines 947-1104):

- The handler is hard-wired around the full 6-block template: `MANAGED_SECTIONS = ['project', 'stack', 'conventions', 'architecture', 'skills', 'workflow']`. It always writes (or refreshes) all six.
- The output path is read from CLI `--output` (or `config.claude_md_path`, defaulting to `./CLAUDE.md`). There is no notion of "which subset of markers belong at this path" — any path you target receives the full template.
- The companion template at `$HOME/.claude/get-shit-done/templates/claude-md.md` says, verbatim: "Template for project-root `CLAUDE.md` — auto-generated by `gsd-tools generate-claude-md`." Root-only by design.

## Result

- `backend/CLAUDE.md` probe overwritten? **No** (probe body survived because the tool flagged it as "manually edited" and skipped that one block — but the tool DID dump 5 other GSD blocks into the file).
- `frontend/CLAUDE.md` probe overwritten? **No** (same — probe body survived, but the tool dumped 5 other GSD blocks into the file).

Critically, "probe survived" is a misleading PASS signal here. The real failure mode is the **opposite** of what the protocol expected: the tool did not refresh the targeted marker in place; instead, it interpreted a scoped CLAUDE.md as a brand-new root CLAUDE.md and tried to instantiate the full template. If we left `<!-- GSD:stack -->` or `<!-- GSD:conventions -->` markers in scoped files, every future `/gsd:docs-update` run would:

1. Skip the scoped marker body as "manually edited" (assuming the prior body still differs from the generator output).
2. Inject the other 5 GSD blocks (project / architecture / skills / workflow / and whichever of stack/conventions wasn't planted) — content totally unrelated to the scoped file's purpose.

That is materially worse than the original "tool can't find the marker" failure mode. It's not a tooling bug to file — it's a contract the tool never had.

## Decision

Tool **cannot** refresh GSD-marker blocks at non-root paths in any usable way → **D-04 fallback applies**.

- **Task 3:** `backend/CLAUDE.md` and `frontend/CLAUDE.md` are written with hand-written content only. No `<!-- GSD:* -->` markers in either scoped file.
- **Task 4:** root `<!-- GSD:stack -->` block stays at root unchanged. Root `<!-- GSD:conventions -->` block keeps **all 3 bullets** at root (frontend, backend, comments) — none of the conventions bullets are split out.
- **Task 6:** the fallback no-op step is the operative path. Task 4 must NOT remove the frontend/backend bullets from root `GSD:conventions`.
- **Task 7 gate #2:** frontend tokens at root are expected (legitimately inside `GSD:conventions` block); the gate is checked via context (substring lives within marker boundaries) rather than blanket-zero.

The substantive moves (Tests, Gemini SDK, alembic deploy line, Next.js 16 warning, `GSD:workflow` block relocation) all still happen as planned — those are hand-written sections, not GSD-marker-managed.

## Probe cleanup

Both scoped files were rewritten to a single-line placeholder comment immediately after this verification ran. Tasks 3 and 4 overwrite them with real scoped content.
