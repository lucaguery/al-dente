<objective>
Fix the 16 test-isolation failures in `test_turns.py` so the suite reports 304 / 0 / 0 (passed / failed / errors). The root cause documented in `37-01-SUMMARY.md` is that several test_turns.py functions call `db_session.commit()` inside the test body, which commits the outer connection-scoped transaction set up by `conftest.py`'s `db_session` fixture. Once committed, the fixture's teardown `rollback()` is a no-op and the seeded member becomes unreachable for subsequent tests.

This is a **prerequisite cleanup** plan: it unblocks Plans 38-02/03/04 by giving them a green starting suite to add tests against. It closes no REQ-IDs directly — it removes a noise floor so COV-01's repo-total measurement at the end of Plan 38-04 is trustworthy.

Purpose: pre-requisite cleanup to honor the per-test rollback contract.
Output: a green suite at 304 passed (or higher if `_seeded_database` also covered tests that were missing).
</objective>

<!-- The current db_session fixture contract (conftest.py:38-52). -->
<!-- It begins a connection-level transaction and rolls back at teardown. -->
<!-- Calling .commit() on the session commits this outer transaction → tests downstream lose isolation. -->

From backend/tests/conftest.py (current shape):

@pytest.fixture(scope="function")
def db_session() -> Generator[Session, None, None]:
    connection = _engine.connect()
    transaction = connection.begin()
    session = _TestSessionLocal(bind=connection)
    try:
        yield session
    finally:
        session.close()
        transaction.rollback()
        connection.close()

The autouse `_seeded_database` (scope=session) commits seed rows ONCE before any per-test transaction begins, so those rows are visible across the suite — fixing this plan must NOT alter that pre-seeded visibility.

SAVEPOINT pattern (option A, recommended):
- Wrap with `connection.begin_nested()` to start a SAVEPOINT after the outer txn.
- Use SQLAlchemy 2.0 event `after_transaction_end` to re-open a nested transaction whenever the test commits the outer-most session-level transaction.
- Outer txn still rolls back at teardown.

Test rewrite pattern (option B):
- Replace `db_session.commit()` with `db_session.flush()` wherever the test only needs writes visible in the same connection (TestClient sees them through the dependency override).

Pick whichever requires the **smaller test-file diff** per task body. SAVEPOINT in conftest = ~10-line addition + zero test edits; flush rewrite = ~14 surgical line edits across test_turns.py.
