### Hook dry-run

Initial attempt (Task 4 first commit, 241f795) revealed a lint-staged
limitation: when the gate script ran as a lint-staged task,
`git add docs/api/*` happened inside lint-staged's stash cycle and was
overwritten when lint-staged restored the index after task completion.
The dry-run commit succeeded but `docs/api/*` was NOT included.

Fix (commit 3229d36): moved router detection out of `.lintstagedrc.json`
into `frontend/.husky/pre-commit` itself — the hook runs `lint-staged`
for ESLint, then inspects `git diff --cached --name-only` for staged
router files and invokes `scripts/openapi_hook_gate.sh` directly. The
gate's `git add docs/api/*` now happens AFTER lint-staged returns, so
the additions stick into the commit index.

Verified by manually pre-dirtying `docs/api/openapi.json`, staging
`backend/app/routers/auth_session.py`, running the gate, and observing
that `docs/api/openapi.json` was restored to canonical content via the
atomic write + re-stage path.

Dry-run trace summary (with blank-line change to `auth_session.py`):

## Deviations from plan

1. **Task 4 split into two commits (241f795 + 3229d36).** The plan's
   single-commit approach put the router-glob trigger inside
   `.lintstagedrc.json`. That ran the gate inside lint-staged's
   stash/restore cycle, and the gate's `git add docs/api/*` was
   silently swallowed when lint-staged restored its tracked file set
   after task completion. Fix: keep `.lintstagedrc.json` for ESLint
   only and move backend-router detection into the husky pre-commit
   hook itself, where `git add` runs OUTSIDE lint-staged's stash
   window. Net: same end-state (gate fires on router stage,
   regenerated artifacts ride along in the commit), cleaner separation
   of concerns. Counts as one "Task 4" architecturally but is recorded
   as two commits for git-history honesty.

2. **`scripts/docs-audit.py` left untouched.** The plan said "inspect
   first; skip if already handles." It uses an explicit allow-list of
   T1/T4/T5 paths and does NOT scan `docs/`, so `docs/api/openapi.json`
   + `docs/api/endpoints.md` never appear in its output. No ignore-
   list entry needed.

3. **Husky `core.hooksPath` resolves to `frontend/.husky/_`, not
   `frontend/.husky`.** This is husky v9's documented internal layout:
   the `_/` subdirectory holds dispatch shims that delegate to
   `../<hook-name>`. Functionally identical to the plan's expectation
   ("husky's directory") — only the literal path string differs.

## Follow-ups

- The auth heuristic in `dump_openapi.py` (`_is_auth_required`) is a
  fallback: it assumes auth-required unless the path is `/healthz` or
  under `/auth/`. A more precise approach would walk the FastAPI
  dependency tree to detect `Depends(current_member)` directly — left
  as productize-later polish.
- Markdown output uses a single tag-group per endpoint (`tags[0]`).
  If FastAPI ever gets multi-tagged endpoints, they'll appear once
  under the first tag only. Acceptable for the current single-tag-
  per-router posture.
- Consider wiring `docs/api/endpoints.md` into the CI step that runs
  on push to `main` so a divergence (e.g. someone bypassed the hook
  with `--no-verify`) gets caught. Out of scope for this quick.
